## 1. 设计支柱

### 1.1 三条支柱

| # | 支柱 | 一句话 | 判定问题（答"否"=违规） |
|---|---|---|---|
| **P1** | 判断优先于运气 | 每 20 秒必须有一次"我看准了" | 玩家这一张票的选择，是否改变了他可能拿到的东西？ |
| **P2** | 进度只进不退 | 没有任何东西会因为时间或失败而变少 | 是否存在清零/衰减/断签扣减？ |
| **P3** | 每三分钟一次跳变 | 数字必须"跳"，不能"爬" | 3 分钟内是否至少一次升级/解锁/大额入账/券到手？ |

### 1.2 支柱的自洽性检查（防支柱打架）

| 冲突可能 | 原因 | 化解规则 |
|---|---|---|
| P1 vs 主导策略 | 三种票型若 RTP 不等，最优解唯一 → 选择退化为"永远选那个" | **三档 RTP 必须完全相等**（5.4 已验证：6 票 × 3 档两两差 <0.01） |
| P2 vs 无限囤积 | 进度不清零 → 玩家可以永远囤运势券不用 | 券上限 2 张，满则必须用掉才能再攒 |
| P3 vs 通胀失控 | 跳变靠倍率 → 倍率爆炸 → 数字失去意义 | 设施成本按"3 分钟收入"阶梯设定（11.3）；`FAC_BONUS` 是唯一通胀阀门 |
| P3 vs 广告缺口 | 跳变太爽 → 玩家不缺票 → 不看广告 | 跳变发生在"金币/设施"轴，票始终是独立闸门（14.2） |

### 1.3 支柱漂移的红旗（评审时逐条查）

| 红旗 | 表现 | 处置 |
|---|---|---|
| 三选一变成"选最贵的" | 票型被忽略，只看面额 | 三档 RTP 审计 |
| 手气槽变成"进度条挂机" | 玩家不看屏幕只等槽满 | 槽只在刮开时 +4，不看广告不给槽 |
| 元游戏变成"数字模拟器" | 升级只有数字变化，没有玩法变化 | 每 5 级必须解锁一个"新东西"（见 11.5） |
| 副循环重新抢戏 | 转盘/广告单次收益 > 3 张票 | G3 门禁脚本校验（PRD 10.1） |

## 2. 诊断 → 解法映射（MDA）

### 2.1 问题清单与对应机制

| 诊断（PRD 一章） | MDA 层 | 缺失的美学 | v2.0 解法 | 为什么能解决 |
|---|---|---|---|---|
| D1 无决策 | Mechanics | Challenge | **三选一 + 预揭格** | 把"买"变成"判断"；信息不完备 → 每次判断都不同 |
| D2 无期待 | Dynamics | Fantasy / Narrative | **手气槽 + 运势券 + 悬赏** | 给"下一次"一个确定的、可视的承诺 |
| D3 数值失序 | Mechanics | — | **SCALE 缩放体系 + 主干优先律** | 所有固定奖励改为"以当前面额为基准" |
| D4 一次一大步失败 | Dynamics | Sensation | **面额 ×20 重定标 + 阶梯成本表** | 首日即万级数字；每 3 分钟一次升级 |
| D5 元游戏缺位 | Mechanics | Expression | **4 设施 + 3 岗位 + 无限扩建** | 金币有永久出口；员工从"产币"改为"产票/加乘" |
| D6 首个 60 秒 | Dynamics | — | **预置槽值 + 必中邀请票 + 无文字引导** | 60 秒内 2 次中奖 + 1 次跳变 |

### 2.2 主干优先律（数值宪法）

> **任一时刻，核心循环（刮卡）的金币/分钟 ≥ 全部副循环（转盘 + 广告 + 悬赏 + 离线）之和 × 3。**

v0.8 违反此律达 99:1，这是"不好玩"的第一结构性原因。v2.0 的检验脚本见 19.7。

| 循环 | v0.8 每分钟金币 | v2.0 D1 | v2.0 D7 | 占比（D1 / D7） |
|---|---|---|---|---|
| 刮卡（主） | 16.3 | 384 | 571,222 | **77% / 98.8%** |
| 转盘（副） | 1,210 | 110 | 6,612 | 22% / 1.1% |
| 悬赏（副，摊薄到分钟） | 0 | 6 | 375 | 1% / 0.06% |
| 离线（副） | 不定 | 不计入分钟（单独封顶） | 同左 | — |

> 计算口径：转盘 = `5.51 × SCALE ÷ 5 分钟`；悬赏 = `3 × 30 × SCALE ÷ 1440`。
> 结论：v0.8 主副比 0.013:1（副循环是主循环的 74 倍）；v2.0 D1 为 3.3:1、D7 为 81:1，全部 ≥3 ✓。
> 副循环在 D1（票最紧时）仍有 22% 的存在感，正是"票用完还有事做"的设计意图；随刮卡收入放大自然退位。

## 3. 理论工具箱

### 3.1 自我决定论映射

| 需求 | 机制 | 强度设计（可调） |
|---|---|---|
| 自主 | 3 选 1 票 / 稳平冲 / 券给谁用 / 设施顺序 / 排班 | 候选数 `PEEK_CANDIDATES`（默认 3，可降 2） |
| 胜任 | 预揭信息可学习；熟练玩家 RTP +8~12% | `PEEK_CELLS`（默认 2，可升 3） |
| 关联 | 22 员工性格 + 店招 + 头衔 | 员工文案量（22 条，见 17.4） |

### 3.2 可变比率强化（Variable Ratio）的正确用法

刮刮乐天然是 VR 强化（不知道第几次中），但**纯 VR 会衰减**（老虎机的衰减曲线是所有赌博机制里最陡的）。v2.0 用**双层结构**对抗衰减：

| 层 | 机制 | 强化类型 | 作用 |
|---|---|---|---|
| 外层 | 三档奖级表（中奖率 3%~62%） | 可变比率 | 提供不可预测的惊喜 |
| 内层 | 手气槽每 10 张必给 1 张券 | **固定比率（FR-10）** | 提供可预测的确定性 |

> 只给 VR → 玩家算不清账，挫败；只给 FR → 无聊。**VR 外套 FR** = 惊喜有底，努力有价。

### 3.3 心流平衡表（挑战 vs 技能）

刮刮乐没有"技能门槛"，所以心流靠**决策难度**而非操作难度调节：

| 阶段 | 决策复杂度 | 认知负荷 | 心流风险 | 对策 |
|---|---|---|---|---|
| D1（0-15 分钟） | 1 个决策（选哪张），信息 2 格 | 低 | 无聊 | 强制出"明显更好"的那张（预揭含 ×10） |
| D3 | 3 个决策（选票/用券/升级谁） | 中 | 心流区 | — |
| D7 | 5 个决策（+排班 +抽卡规划） | 中高 | 焦虑 | 所有决策都有"推荐"高亮，可一键采纳 |
| D30 | 5 个决策 + 长线规划 | 高 | 焦虑 | 无限扩建只给数字，不给新规则（不再加认知） |

> **认知红线**：一级界面上同时可见的"可决策元素"≤ 3 个。超过就折叠。

### 3.4 损失厌恶的反向使用

| 传统博彩 | 机制原理 | 我们的反向用法 | 代码落点 |
|---|---|---|---|
| 输了想赢回 | 损失厌恶 | 不存在"输掉已有资产" | 无任何扣减逻辑（P2） |
| 差一点中 | near-miss 错觉 | 用"预揭 2 格"给**真实**信息 | `peekCells` |
| 限时逼单 | 稀缺焦虑 | 用"确定性倒计时"给安心 | `luckGauge` 显示"再 N 张" |
| 沉没成本 | 投入越多越难走 | 用"资产越攒越舍不得" | 图鉴/设施/头衔 |

## 4. 四层循环

### 4.1 总图

```
[20-45 秒] 单张票（按档位，8-40 局）
  票架挑档 → 单张/整本 → 看 3 张候选（各露 2 局）→ 选 1 张
  → 逐格刮（每格一次判定）→ 三区合计 → 进待兑口袋 → 槽 +4
        ↓ 累积 8-10 张
[3 分钟] 一轮
  槽满 → 运势券 → 券给谁 → 口袋攒够 → 整叠兑奖 → 设施/刀升级
        ↓ 累积 3-4 轮
[15 分钟] 一次会话
  补票 A1 / 磨刀 A6 / 兑奖 A7 / 免费票加速 A8 / 十连 / 排班 / 离线计时
        ↓ 累积 1 天
[跨天] 回访
  签到 / 悬赏刷新 / 连登解锁霜花 / 离线收益 / 周悬赏
```

### 4.2 逐层拆解（决策点 → 反馈 → 下一步）

#### 第 1 层：20-45 秒（单张票，v2.1 按档位）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①票架上挑哪一档（5/10/20/30/50）②单张还是整本 ③3 张候选中选 1 张（依据预揭的 2 局内容 + 票型）④运势券是否要用 | 每分钟 2-4 次决策，全部"一眼可判" |
| **反馈** | 刮除手感（三层阻力）→ 逐格揭晓（命中格点亮，音高递进）→ 区合计 → 三区总计 → 票奖级 → 待兑口袋 +1 → 手气槽 +4 | "我选对了"的即时确认，且**每张票给 8-40 次微反馈** |
| **下一步** | 槽进度 / 口袋距整叠加成还差 N 张 / 锋利度低 / 图鉴盖章 | 每一次结算都留下一个未完成的承诺 |

> **决策密度校准（v2.1）**：单张加权 29.3 秒 → 2.05 张/分钟 → 每分钟约 2.05 次选票决策 + 0.3 次用券 + 0.5 次"单张/整本"≈ **2.9 次/分钟**，仍满足 PRD ≥2 次门禁。
> 更重要的不是决策密度，而是**判定密度**：每分钟 5.3 × 15.6 局 ≈ **82 次"这格对不对"的判定**（v2.0 是 2.4 次）。这是"可玩性"的可观测代理指标，见 PRD 8.3 埋点 `round_reveal`。

#### 第 2 层：3 分钟（一轮 6-8 张）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①运势券用在哪种票上（存还是用）②金币升级哪个设施（4 选 1）③继续买票还是去转盘 | 从"判断"升级到"配置"，产生策略感 |
| **反馈** | 设施升级后立刻可见的数值跳变（"柜台 Lv5：单张奖金 +15%"）；券打出的大额入账（≥ 面额 5 倍） | **P3 支柱的落点**：每 3 分钟一次跳变 |
| **下一步** | 结算页只显示一个引导：「再刮 6 张解锁「烫金」」或「升级柜台需 13,000 币，还差 2,100」 | 单一引导，不做并列选项（防选择过载） |

#### 第 3 层：15 分钟（一次会话）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①票不够：等 2:47 还是看广告（等权按钮）②有 1,600 钻：单抽还是攒十连 ③员工排班：柜台还是后场 | 3 个决策都属于"资源配置"，时长 15 分钟内自然发生 |
| **反馈** | 悬赏完成弹出（带实物感奖励）；抽卡动画分级；离线计时开始（显示"8 小时后回来可得 N 张票"） | 会话末段给"关掉的理由"+"回来的理由" |
| **下一步** | 离线面板预告：`离店 8 小时 → 票 +N、金币 +N` | 把"下次什么时候来"写死成数字 |

#### 第 4 层：跨天

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①签到选第几档（连续奖励递增）②周悬赏的目标票种 ③无限扩建投哪个设施 | 低频高权重决策 |
| **反馈** | 头衔晋升全屏仪式；图鉴完成度；连登天数 | 身份感（SDT 关联） |
| **下一步** | 连登 3 天解锁「霜花」（D3 核心钩子）；周悬赏倒计时"还剩 3 天" | D1/D3/D7 的具体回访理由见 12.5 |

### 4.3 首个 60 秒（分秒脚本）

> 目标：60 秒内完成"2 次中奖 + 1 次跳变 + 理解 3 个系统"，且**全程没有一句教学文字超过 12 个字**。

| 时间 | 屏幕 | 系统动作 | 设计原理 |
|---|---|---|---|
| 0.0-3.0s | 声明页（唯一可跳过项：一键"我已了解"） | 写 `first_launch`，生成存档 | 合规 + 先给确定性 |
| 3.0-6.0s | 柜台页，3 张候选票依次入场（0.08s 延迟） | `rollCandidates(5)`，但第 1 张走 `rollFirstTicket()`：5 元档 8 局，**固定 2 局命中**（1×和 1×，合计 2,000 币），预揭 2 局均为命中局 | 第一眼就有"可判断的信息" |
| 6.0-9.0s | 第 1 张票上浮 6px（呼吸动画），其余两张压暗 20% | 只高亮 1 张，不强制 | 视觉引导代替文字 |
| 9.0-12.0s | 手指虚影划一下（1.5s 循环） | 首张笔刷半径 ×1.4（10 → 14 dp） | 降低第一次操作挫败 |
| 12.0-20.0s | 刮除 8 局 → 100% 自动结算 | 逐格揭晓，命中的 2 格单音上行 | 刮感第一次建立 |
| 20.0-24.0s | 结算：合计 2,000 币（回本 ×2 → 三等奖档） | 三等奖反馈（0.8s）+ 合计滚动 | 首张必中，且金额刚好够买铜刀 |
| 24.0-26.0s | 票进「待兑口袋」→ 引导去兑奖台 | 口袋 1/30，页脚亮一下 | 立刻教"兑奖"这个动作 |
| 26.0-30.0s | 兑奖：1 张，普通揭晓 2.5 秒，入账 2,000 | 只给一个动作 | 30 秒内完成"刮→兑"闭环 |
| 30.0-38.0s | 手气槽 32/40（预置值），文案"再 2 张，有张运势券" | `luckGauge = 32` 写死 | 立刻给出一个 2 步可达的终点 |
| 38.0-50.0s | 自动回柜台，3 张新候选，其中一张（稳型）预揭露出 2 个命中局，另一张只露 1 个 | 第 2 张候选保证预揭"好看" | 让玩家自己发现"要看预揭" |
| 50.0-60.0s | 玩家选中 → 刮开（命中）→ 槽 36→40 → **运势券到手** → 引导"柜台升 Lv.2 需 6,000 币"（差额补足） | `vouchers = 1`；补足金币让第一次升级可达 | 第 60 秒完成第一次"跳变"（P3 支柱） |

**三个硬约束**：

## 5. 系统 A：柜台三选一（核心机制）

> **v2.1 状态：5.2 / 5.3 / 5.4 / 5.5 的"单奖级 × 6 票 × 18 张表"已被取代。**
> 现行权威是 **J（10 票 / 5 档 / 多局结构）+ 14.5（EV 公式）+ 19.9（30 张表 CSV）**。
> 本章保留的是**三选一的交互骨架**（5.1 / 5.2 的候选生成逻辑 / 5.6 预揭 / 5.7 配额），这些都仍然有效；
> 下方 5.3-5.5 的赔付数字**仅作历史留痕，不得作为实现依据**。

### 5.1 这是什么

把 v0.8 的「点票种 → 直接买 → 刮」改成「进柜台 → 系统给 3 张同面额、不同票型的候选票（各预揭 2 格）→ 你选 1 张 → 刮」。

**唯一目的**：在不改随机数、不改合规边界的前提下，造出每秒都在发生的真实决策。

### 5.2 候选票生成

```
生成时机：每次进入柜台页（或点"换一批"）
生成数量：3 张（PEEK_CANDIDATES）
票型分配：稳 / 平 / 冲 各 1 张（顺序随机打乱）
面额：当前选中的票种面额（三张同面额、同价格）
预揭：每张随机挑 2 格揭开（福彩 = 9 格中的 2 格；M10 = 10 注中的 2 注）
```

**关键约束（不可妥协）**：

| 约束 | 说明 |
|---|---|
| 三张票各自独立走「先抽奖级、再倒填符号」流程 | 遵守 `docs/结果生成规范.md`；预揭格是**该票真实结果的子集**，不是伪造 |
| 三档 RTP 完全相等 | 见 5.4；差 >0.01 即出现主导策略 |
| 预揭格随机取样，不偏袒 | 不许"为了让玩家选中而挑好看的格子"（除首张引导票，见 4.3） |

### 5.3 三种票型（稳 / 平 / 冲）

三张票**同一价格、同一面额、同一 RTP**，只在"奖级配比"上不同：

| 票型 | 名称 | share 向量（三等奖/二等奖/一等奖/特等奖） | 中奖率（T1） | 玩家感知 |
|---|---|---|---|---|
| `steady` | **稳** | 0.86 / 0.12 / 0.018 / 0.002 | 62.1% | 「常有小惊喜」——新手默认高亮 |
| `normal` | **平** | 0.62 / 0.28 / 0.09 / 0.01 | 29.7% | 「正常手感」 |
| `wild` | **冲** | 0.30 / 0.40 / 0.24 / 0.06 | 11.0% | 「一把见分晓」——特等奖概率是稳的 33 倍 |

> **v2.1 说明**：本节的"单奖级 → 单次赔付"模型已被多局模型取代。现行的票型定义在 **14.5**（`E[K] × E[m] = RTP`，票型改的是 `K` 形状与倍数池权重）。下方公式与 5.4/5.5 的 18 张表**仅作历史留痕**。

**概率解算公式（v2.0 版，已被 14.5 取代）：**

```
给定：面额 P、目标 RTP R、赔付向量 v = [v3, v5, v7, v9]
     票型 share = [s3, s5, s7, s9]（Σs = 1）

中奖率 W = (R × P) / Σ(s_j × v_j)
p_j     = s_j × W          （j = 3/5/7/9）
p_0     = 1 − W
```

> 数学性质：因为 W 被分母归一化，`Σp_j × v_j ≡ R × P`，**三档 RTP 恒等**。这是"无主导策略"的数学证明，不是调试结果。

### 5.6 预揭格（PEEK）——整个 v2.0 的支点

**规则**：每张候选票在购买前，随机挑 `PEEK_CELLS = 2` 格揭开，永久可见（购买后这 2 格已算刮开，计入 100% 进度）。**v2.1：预揭以"局"为单位**——比对/符号/金额类揭 2 个格；凑齐三个类（D 判定）揭 1 整局（3 格），因为半局无法判断。

| 票种 | 预揭内容 | 例子 |
|---|---|---|
| 福彩 6 票 | 2 格符号 | 「这张露出：福、福」→ 已锁定 2 个匹配，至少是三等奖 |
| 好运十倍 | 2 注的号码 + 奖金 + 是否 ×10 | 「第 3 注：号码 17（对照号 17）奖金 300 ×10」→ 已被锁 3,000 |
| HOT 全收 | 3 格金额（不揭 HOT 位） | 「400 / 12,000 / 4,000」 |

**为什么这不破坏概率**：预揭是结果生成后"提前揭开"的格子，不参与随机决策 → 每张票的边缘分布不变，公示表仍然准确。

**已知副作用（必须承认并调参）**：玩家会挑"露得好的"那张，于是**实际 RTP 高于公示的每票 RTP 约 +8~12%**。

| 处理 | 说明 |
|---|---|
| 定性 | 视为**特性**（奖励判断力），不是 bug。这是"选择有用"的证明，也是 P1 支柱的量化落点 |
| 监控 | 埋点 `choice_regret`（选中票 vs 未选中票的收益差）。若差值 <5%，说明预揭无信息价值，需加到 3 格 |
| 阀门 | `PEEK_CELLS` 2 → 1 可把选择增益砍半；经济过热时优先动这个，不要动 RTP 表 |
| 合规 | 公示页加一行：「每张票的 2 格在购买前即已揭开，选择不同票会影响你实际获得的平均回报。」——**说清楚比藏着安全** |

### 5.7 购买与配额

v0.8 的"有免费票用免费票，没票用金币买"保留，但**金币买票加日配额**——否则金币会绕过票闸门，广告位 A1 彻底失效（v1.1 模拟已证明 A1 对轻度玩家触发率为 0）。

| 支付方式 | 消耗 | 限制 |
|---|---|---|
| 免费票 | 1 张票 | 票池上限 `TICKET_CAP` |
| 金币 | 面额 P | **日配额** `BUY_CAP = 30 + 2 × (迎宾等级 − 1)` |
| 运势券 | 不额外消耗 | 上限 2 张 |

> 配额用完后，按钮变「今日柜台已售完 · 明天再来」并给两个等权出口：「看广告 +20 票」/「等 2:47 自然恢复」。

## 6. 系统 B：手气槽与运势券

### 6.1 为什么是"固定值"而不是"未中才加"

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 未中 +3 / 中奖 +1 | 心理补偿强 | **造成主导策略**：冲型未中率 89% → 槽涨得快 3 倍 → 理性玩家永远选冲 | 否决 |
| 中奖才加 | 奖励准确 | 手气差时看不到希望，违背解压定位 | 否决 |
| **固定 +4/张** | 可预测、无套利、可承诺 | 惊喜感弱 | **采用** |

> 固定值还带来一个隐性收益：进度条变成"确定性倒计时"（"再 6 张"），比"概率性进度"更能驱动回访——这正是损失厌恶的反向使用（确定性替代焦虑）。

### 6.2 数值

| 参数 | 值 | 字段名 | 说明 |
|---|---|---|---|
| 每张增益 | +4 | `LUCK_GAIN_PER_TICKET` | 任何票种、任何票型都一样 |
| 槽容量 | 40 | `LUCK_CAP` | = 每 10 张出 1 张券 |
| 券上限 | 2 | `VOUCHER_MAX` | 满 2 张后槽不再累积（强制消耗） |
| 券保证档 | 至少 1 局命中，且该局金额 ≥ 2× 面额 | `VOUCHER_MIN_HITS` / `VOUCHER_MIN_M` | v2.1 语义：保证"有一笔像样的中奖" |
| 跨天 | 不清零 | — | P2 支柱 |
| 跨票种 | 通用 | — | 防止"只玩一种票"的碎片化 |

### 6.3 运势券的三个决策点（v2.1 重写）

| 决策 | 选项 | 为什么有意思 |
|---|---|---|
| 现在用还是存着 | 存（上限 2） | 票价档越高，券的绝对值越大 → 天然鼓励"等解锁更高档" |
| 用在哪张票型上 | 稳 / 平 / 冲 | 券保证"1 局 ≥2×"。在**稳型**上几乎必然发生（68% 中奖率），券近乎浪费；在**冲型**上等于"用 42% 的概率换 100% 拿到一笔 ≥2×"，价值最大 → 明显应该配冲型 |
| 用在哪一档票上 | 5 / 10 / 20 / 30 / 50 | 券的绝对值随票价档线性放大（50 档一局 ≥2× = 2 万），但 50 档局数最多、命中概率最高，券的边际价值反而下降 → **最优是 20-30 档**（价值与稀缺的交叉点） |

> **券 × 冲型 × 20-30 档** 是最优组合——这是设计好的"组合技"：手气槽提供确定性，冲型放大确定性，20-30 档提供最大的绝对金额。玩家自己发现这个组合时会觉得自己很聪明（胜任感）。

### 6.4 状态机

```
槽值 < 40       → 每刮完一张 +4，UI 显示 "手气槽 32/40 · 再 2 张有券"
槽值 = 40 且 券 < 2 → 券 +1，槽归零，播放"券入手"动画（0.8 秒）
槽值 = 40 且 券 = 2 → 槽停在 40/40，UI 提示"先用掉一张运势券"
用券刮票       → 生成时强制 K ≥ 1，且至少 1 个命中格的 m ≥ 2.0
```

> **实现要点（v2.1）**：用券时先按票型的 `K 分布` 正常抽 `K`；若 `K = 0` 则重抽直到 `K ≥ 1`；然后保证抽出的 `m` 里至少一个 ≥2.0（不够就把最小的那个抬到 2.0）。**这个抬升不改变票的公示概率**，因为它是"券的效果"，公示页只公示票本身的分布，券的效果单独一行说明。

## 7. 系统 C：好运十倍（v2.1 拆为「雨后」+「对折」）

### 7.4 生成算法（先定注数，再倒填；已被 19.1 的 `generateTicketV3` 取代）

```
function generateM10(profile):
    hitCount = weightedPick(hitsDist)           // 0/1/2/3
    winningNumber = randomInt(1, 40)
    entries = array(10)

    hitSlots = randomChoose(10, hitCount)       // 哪几注命中
    for i in 1..10:
        if i in hitSlots:
            number = winningNumber
            prize  = pick(pool)
            mult   = (random() < p10) and 10 or 1
        else:
            number = randomInt(1,40) excluding winningNumber
            prize  = pick(pool)                 // 不命中也要显示奖金，制造"差一点拿到"的视觉张力
            mult   = 1
        entries[i] = { number, prize, mult }

    // 预揭：随机挑 2 注标记为已揭开
    peek = randomChoose(10, 2)
    return { winningNumber, entries, peek }
```

**注意**：不命中的注也显示奖金（真票就这样）。这是视觉张力来源，但**不构成"差一点"暗示**——因为未中注的号码是随机生成的，与对照号无关联，且未中奖界面不给任何"就差一个"的提示（见 7.6）。

### 7.5 表现规范

| 时刻 | 表现 |
|---|---|
| 预揭注 | 已揭开的 2 注有 2px 金色描边 + 角标「已露」；其余 8 注覆银色涂层 |
| 刮开命中注 | 该注整注高亮 + 号码闪烁 2 次 + 单音「叮」 |
| 刮开 ×10 命中注 | 全屏短暂（0.15s）压暗 + 该注放大 1.2 倍 + 「×10」金漆质感 + 低音「咚」 |
| 结算 | 命中注按注数逐条累加（每注 0.25s），最后给合计 |
| 0 命中 | 0.4 秒静默 → 极轻的「沙」一声 → 自动回柜台，不做任何文字提示 |
| 多注命中 | 累计到第 3 条时追加一句「今天手气可以」（仅此一句） |

### 7.6 与福彩的差异（为什么要两个主干）

| 维度 | 福彩 6 票 | 好运十倍 |
|---|---|---|
| 认知负荷 | 低（找相同） | 中（对号码） |

## 9. 系统 E：转盘（SCALE 化）

### 9.1 为什么必须改

v0.8 的转盘单次金币期望 6,050，是晨光票（EV 6.8）的 **890 倍**。玩家最优策略是"等电、转盘、别刮票"。v2.0 用 `SCALE` 基准把转盘收益锚定在"当前主力票"的尺度上。

### 9.2 SCALE 定义（v2.1 已重定义，见 14.2）

```
-- v2.1 版（现行）
SCALE = 当前已解锁最高票的 coinPrice
      （5 元:1,000 → 10 元:2,000 → 20 元:4,000 → 30 元:6,000 → 50 元:10,000）
-- v2.0 版（作废）：SCALE = T1:100 → T6:100,000
```

> 转盘、悬赏、刀价、磨刀成本等所有 `k × SCALE` 公式**结构不变**，只是 SCALE 的量级从 100-100,000 变成 1,000-10,000（约降 10×）。扇区表（9.3）的系数**不改**。

## 11. 系统 G：店铺经营（元游戏）

### 11.1 经营如何让"数字膨胀"有意义

数字膨胀本身是廉价的（改个乘数就行）。它有意义，靠三件事：

| 载体 | 玩家感知 | 数值落点 |
|---|---|---|
| **看得见的柜台** | 桌面 → 柜台 → 整层 → 一条街（4 个视觉阶段） | 柜台等级 1-10 / 11-20 / 21-29 / 30 |
| **单张票的收益翻倍** | "同样刮一张，现在给 3 倍" | 柜台 +15%/级 |
| **能刮的票变多** | "以前一天刮 40 张，现在 200 张" | 迎宾 + 员工柜台岗 |

> 一句话：**数字膨胀必须落在"我每一次动作的产出"上，而不是"我的仓库里有个大数字"。**

### 11.2 四个设施（v2.0 核心新增）

| 设施 | 效果（每级） | 上限 | 解锁 | 字段名 |
|---|---|---|---|---|
| **柜台** | 刮卡奖金 **×1.15**（复利） | 30 | 默认 | `FAC.counter` |
| **迎宾门** | 票恢复速度 +6%；票池上限 +15；金币买票配额 +2 | 30 | 默认 | `FAC.door` |
| **招财猫** | 员工产出 +6%（复利）；离线封顶 +0.25 小时 | 30 | 累计刮满 15 张 | `FAC.cat` |
| **转盘台** | 转盘金币 +15%；电上限 +1；电恢复 +4% | 30 | 累计刮满 15 张 | `FAC.wheel` |

> 效果都是**复利**（`1.15^lv`），不是线性加法。原因：线性加成在 D7 后会被通胀淹没，失去"跳变"感。

### 11.3 柜台升级成本表（30 级，阶梯式）

### 11.4 无限扩建（30 级后）

```

  成本 = 柜台30级成本 × 3^(n−30)
  效果 = 每级 +8%（加法，非复利，避免爆炸）
  无上限
```

## 系统 J：真实票种对标与多局结构（v2.1 新增）

### J.0 前置裁决：面额体系（三选一，必须给结论）

v2.0 刚把面额从 5-5000 重定标到 100-100,000（×20），追求数字膨胀。但真实票只有 5 / 10 / 20 / 30 / 50 五档，且用户明确要"10 块 20 块的热门票"那种真实感。两者的冲突点只有一个：**票面上那个数字，到底是"元"还是"币"**。

| 方案 | 做法 | 数字膨胀 | 真实感 | 代价 | 裁决 |
|---|---|---|---|---|---|
| **A 真实面额派** | 票价就是 5/10/20/30/50 币 | 崩（首日 200 币） | 满 | 全经济表推倒重写，首日数字倒退两个量级，用户"太水"的投诉会原样复发 | ✗ |
| **B 膨胀派** | 维持 v2.0 的 100 → 100,000 六档，票名与档位脱离真实票 | 满 | 零（玩家看不出这是"10 块的票"） | 用户诉求 1（真实票同构）直接落空 | ✗ |
| **C 混合派（采用）** | **面额是真实档位（5/10/20/30/50 元，只印在票面上），票价用金币（1 元 = 200 币 → 1,000/2,000/4,000/6,000/10,000 币），纵向膨胀改由"柜台倍率 × 局数"承担** | 中（首日 3 万，D30 30 亿） | 满 | 面额跨度从 1000× 压到 10×，D30 存款比 v2.0 锚点低约 10 倍 | **✓ 采用** |

**选 C 的三条理由**：

1. **真实感是这一轮的唯一新增资源，不能拿它换数字。** 票面上印着「10」，柜台标价「2,000 币」，最高奖印「160 万」——这三行字一出现，玩家立刻认出"这就是我刮过的那种票"。换成「面额 2,400 币」，同构关系断掉，前面所有对标工作归零。
2. **数字膨胀的力量本来就不在面额上。** v2.0 的膨胀靠"换更贵的票"，那是**横向涨价**；玩家感知是"票变贵了"，不是"我变强了"。v2.1 把膨胀移到**柜台倍率（1.15^29 = ×57）+ 局数（8 → 40）+ 后场岗 + 图鉴**，感知是"同样一张 10 块的票，我现在刮出 20 万"。后者才是"我变强了"。
3. **面额跨度压到 10× 反而解锁了两个新自由度**：① 五档票可以**同时**存在（不再串行解锁，玩家第一天就能看见 50 档票），"看得见但买不起"是最强的长线钩子；② 高档票靠"局数多"而不是"面额大"来体现价值，这与真实票的规律完全一致（50 元票的价值是 40 次机会，不是"50 元"）。

**明确的取舍代价（记入风险）**：D30 存款从 v2.0 锚点的 300-1500 亿降到 30-100 亿；14.4 的锚点表全表重算（见 14.4 修订行）。换来的是**每张票的参与深度从 1 次判定提升到 8-40 次**。

### J.1 诊断 D7：一张票只有一次判定

| 维度 | v0.8 / v2.0 | 真实即开票（298 款实测） | 差距 |
|---|---|---|---|
| 单张独立判定次数 | 1（9 格凑 3 个 = 1 次结算；M10 的 10 注只结算"命中注数"一次） | **8-50 次**（5 元档 8-10 次，50 元档 35-50 次） | 8-50× |
| 单张时长 | 20-26 秒 | 实体 40-120 秒 | — |
| 每 10 秒"中/不中"反馈 | 0.4 次 | 3-6 次 | 10× |
| 刮除动作是否承载信息 | **不承载**（刮完才知道，刮的过程只是劳动） | 承载（每刮开一格就是一次判定，随时可能"对上"） | 本质差异 |
| 一张票的奖金来源 | 单一奖级赔付 | Σ 各命中局奖金 | — |

> **这是 v2.1 唯一的结构性改动，也是"可玩性"三个字的唯一真实来源。**
> v2.0 把"刮"当成"延迟揭晓的抽奖"，去掉刮除动作体验完全等价——这就是"太水"。真实票不是这样：真实票的每一格都是一次小判决，玩家的手在刮、眼睛在找、脑子在算，**刮除本身就是玩法**。
> 用户说"可以刮很多的这种"，翻译过来是：**把 1 次判定拆成 N 次判定，让刮的过程承载信息**。

### J.2 五种判定在引擎里的实现

真实票 298 款的玩法名称五花八门，判定逻辑只有 5 种（手册第四章结论）。这 5 种我们全部实现，且全部落在"格"这一层，不需要新引擎能力：

| # | 判定 | 真实票原型 | 引擎实现 | 一"局"是什么 | 我们的票 |
|---|---|---|---|---|---|
| A | **刮到金额** | 奖金即中（"刮出任何奖金金额即可获得"） | 格内显示金额；金额本身即命中 | 1 格 = 1 局 | 烫金 / 长卷 / 霜花 |
| B | **刮到符号** | 图符即中（刮出"福"得下方奖金） | 格内显示符号 + 金额；符号 = 目标符号即命中 | 1 格 = 1 局 | 灯芯 / 压纹 |
| C | **对上号码** | 比对中奖（我的号码 vs 中奖号码） | 顶部 N 个"幸运号"常显；格内显示号码 + 金额；相同即命中 | 1 格 = 1 局 | 雨后 / 对折 / 长卷 |
| D | **凑齐三个** | 三同 / 两同中奖 | 3 格为一"局"；三格同符号即该局命中，得该局右侧金额 | 3 格 = 1 局 | 晨光 / 夜光 |
| E | **乘倍数** | 倍数加成（×2/×5/×10） | 格额外字段 `mult`；命中时金额 × mult | 叠加在 A/B/C/D 上 | 压纹 / 晨光 / 夜光 |

**实现约束（不可妥协）**：

| 约束 | 说明 | 原因 |
|---|---|---|
| 结果是**先定、后填** | 先抽 `命中格数 K` 与每命中格的 `奖金倍数 m`，再倒填格内符号/号码 | 沿用 `docs/结果生成规范.md` 的核心修正；公示表才是真概率 |
| 未命中的格**也印金额** | 真票就这样（每格都有奖金，只是对不上） | 视觉张力来源；但**不给任何"差一点"提示**（PRD A1） |
| `mult` 只出现在命中格 | 未命中格的 `mult` 恒为 1，不显示 ×N 角标 | 防止"差一点就 ×10"的 near-miss 暗示 |
| 判定数 = 格数（除 D 类） | 一张票的"中奖机会次数"= 局数，与真实票口径一致 | 票面文案要能写"共 20 次机会" |

### J.6 单张时长模型（"打发时间"的核心数值）

```
T_scratch = 0.95 × A_cover / (SCRATCH_RATE_BASE × k_eff)      -- 刮除秒数
k_eff     = k_blade × (0.70 + 0.30 × sharp/100)               -- 有效效率
T_total   = T_scratch + 0.18 × 局数 + 2.5                     -- 含逐格揭晓与结算
```

| 变量 | 含义 | 单位 | 默认 |
|---|---|---|---|
| `A_cover` | 该档票的涂层总面积 | dp² | 见 J.5 |
| `SCRATCH_RATE_BASE` | 基准覆盖速率（实测校准值） | dp²/秒 | 3,300 |
| `k_blade` | 当前刀的基础效率系数 | — | 1.00-1.90（见 K.3） |
| `sharp` | 锋利度 0-100 | 点 | 见 K.4 |
| `0.95` | 只算 95% 涂层（剩 5% 自动补齐，见 15.3） | — | — |
| `0.18 × 局数` | 逐格点亮动画（每局 0.18 秒） | 秒 | — |

**五档时长表（k=1.00 / sharp=100）**：

| 档位 | `A_cover` | `T_scratch` | 逐格揭晓 | 结算 | **`T_total`** | 满级刀 `T_total`（k=1.90） | 钝刀 `T_total`（k=0.70） |
|---|---|---|---|---|---|---|---|
| 5 元 | 50,000 | 14.4 | 1.5 | 2.5 | **18.4 秒** | 10.1 | 23.0 |
| 10 元 | 76,000 | 21.9 | 2.2 | 2.5 | **26.6 秒** | 14.0 | 34.9 |
| 20 元 | 106,000 | 30.5 | 3.6 | 2.5 | **36.6 秒** | 19.4 | 48.5 |
| 30 元 | 132,000 | 38.0 | 5.0 | 2.5 | **45.5 秒** | 23.5 | 60.5 |
| 50 元 | 138,000 | 39.7 | 7.2 | 2.5 | **49.4 秒** | 25.5 | 66.1 |

**自校验（这张表能证明布局没写错）**：反解五档所需速率 `RATE = 0.95 × A_cover / T_target`，若五档结果落在同一区间，说明"面积"与"目标时长"自洽：

| 档位 | 目标时长 | 反解所需 RATE |
|---|---|---|
| 5 元 | 15 秒 | 3,167 |
| 10 元 | 22 秒 | 3,275 |
| 20 元 | 30 秒 | 3,366 |
| 30 元 | 36 秒 | 3,470 |
| 50 元 | 42 秒 | 3,128 |

→ 五档反解值落在 3,128-3,470，取自 3,300 时误差 <6%。**这就是 3,300 的出处**，不是拍脑袋。

**回答"格子多了单张会涨到多少"**：

| 口径 | v2.0 | v2.1 |
|---|---|---|
| 单张时长 | 20-26 秒（全票种） | **18-49 秒（按档位）**，加权平均 29.3 秒 |
| 单张判定次数 | 1 | 8-40（加权平均 15.6） |
| 每 10 秒判定次数 | 0.4 | **5.3** |
| 单次会话（14 分钟）张数 | 34 张 | 29 张 |
| 单次会话总判定次数 | 34 | **452**（×13） |

> **"多玩 10 分钟"的答案**：不是单张变长，是**单张的信息密度变了**。同样 14 分钟，v2.0 给玩家 34 次"中/不中"，v2.1 给 452 次。人不会因为"刮得久"多留 10 分钟，但会因为"这格到底对不对"多留 10 分钟。

### J.7 刮除性能（NanoVG 逐格重绘的边界）

| 项 | v0.8 现状 | v2.1 目标 | 预算 | 结论 |
|---|---|---|---|---|
| 最大格数 | 16（HOT） | **40** | — | 2.5× |
| UI widget 数 | 36（cell + foil） | 80 | <120 | ✓ |
| NanoVG 每帧矩形 | 324（`drawFoilRect` 按 18×18 蒙版） | ≤40（只画未揭晓格）+ ≤120（子块） | <250 | ✓ 与 v0.8 同量级 |
| 触摸判定 | 包围盒内格 × 1 | 包围盒内格 × 4 子块 | <100 次/帧 | ✓ |
| 帧率 | 30 fps | 30 fps @ 骁龙 660 | 33 ms/帧 | ✓ |

**实现方案（不改引擎，只改绘制策略）**：

| 决策 | 内容 | 理由 |
|---|---|---|
| 格内容走 UI Panel，涂层走 NanoVG | 已成立：`buildScratchScreen` 建 Panel，`DrawFoil` 走全局渲染钩子 | 文本排版交给 UI 库，重绘交给立即模式 |

### J.8 「多局」与「多区」：两个必须分开的概念

| 概念 | 定义 | 数量 | 玩家感知 | 实现 |
|---|---|---|---|---|
| **局（round）** | 一次独立判定单元，产出"中/不中 + 该局奖金" | 8-40 | 「这一格对上了没有」 | 一个格（或 3 格，D 类判定） |
| **区（zone）** | 一个玩法区，有自己的标题、幸运号、规则，内含多个局，**区与区兼中兼得** | 1-3 | 「这一摊我刮完了，还有下一摊」 | 独立的 `rect` + 独立 `cols/rows` + 独立幸运号 |

**为什么必须区分（而不是"40 格铺满一屏"）**：

| 理由 | 说明 |
|---|---|
| 可读性 | 40 格单区 → 单格 <48dp，号码与金额挤不下；3 区后每区自己能给 56dp |
| 节奏分段 | 49 秒的票如果是一条连续长刮，玩家在第 20 秒就会疲劳；3 区 = 3 个"小终点"（每区刮完该区合计先亮一次），把 49 秒拆成 3 段 16 秒 |
| 玩法差异可见 | 「玩法一 · 对号 / 玩法二 · 找符号 / 玩法三 · 刮金额」三行标题，让玩家在 3 秒内理解"这张票有 3 种玩法"——这是真实票最重要的"值钱感"来源 |
| 兼中兼得的爽感 | 区间独立结算 → 玩家会经历"区 1 没中（沮丧）→ 区 2 中两格（翻盘）"，一条连续判定给不了这种情绪反转 |

**区的结算顺序（固定，不可调）**：区 1 刮完 → 区 1 合计先亮（0.5 秒，只显示该区）→ 区 2 → 区 3 → 三区总计滚动 → 进待兑口袋。

### J.9 整本购买（批量 1 / 10 / 50 / 100 的真实对应）

真实彩票有"整本"概念（一本 20-50 张连号）。录屏里的"批量购买 1/10/50/100"就是它的游戏版。**但整本与三选一必须给出不同的最优解，否则其中一个会废掉**：

| 项 | 单张（三选一） | 整本 |
|---|---|---|
| 数量 | 1 张 | 10 / 20 / 50 张（同票种同档，一次扣款） |
| 单价 | 面额 × 1.00 | 面额 × **0.95**（-5%） |
| 预揭 | 每张 2 格 | **无预揭**（真实整本也没得挑） |
| 决策 | "挑哪张" | "挑单张还是买一本" |
| 连号彩蛋 | — | 一本 10 张中 **≥8 张中奖** → 额外赠 1 张同款票 |
| 刮除 | 逐张手动 | 逐张手动（**不可一键**，见 20 章 #13） |
| 设计意图 | 期望值路径（预揭增益 +8~12% RTP） | 点击效率路径 + 保底彩蛋 + "整叠兑奖"的仪式前置 |

**无主导策略校验（必跑）**：

```
单张路径 EV = RTP × (1 + PEEK_GAIN)                 ≈ 1.70 × 1.10 = 1.870
整本路径 EV = RTP × 0.95 的票价折扣 × (1 + 彩蛋EV)  ≈ 1.70 × 1.053 × (1 + 0.033) = 1.885
```
两条路径偏差 <1%，**都成立**。监控埋点 `book_vs_single`（每千张收益差），偏差 >8% 时调 `BOOK_DISCOUNT` 或 `BOOK_EGG_P`。

> **保底彩蛋概率**：`P(≥8 张中奖 | 单张中奖率 0.578, n=10) ≈ 5.5%`，彩蛋价值 = 1 张票价 → EV = 0.055 × 1,000 = 55 币 = 2.75% 票价 ≈ 1.7% RTP。用 `BOOK_EGG_P` 直接标定，不依赖二项式近似。

## 系统 K：刮刀与次数经济（v2.1 新增）

### K.1 三条红线（写死，不可谈判）

| # | 红线 | 为什么 |
|---|---|---|
| 1 | 刮刀**只买速度**，永远不买结果 | 任何刀具都不改 `p`、`RTP`、`奖金倍数池`。刀是 `k_eff` 的唯一外部输入，与随机数完全隔离 |
| 2 | **钝刀仍能刮完** | `k_eff` 最低 0.70×，不存在"必须换刀才能继续"。付费墙一旦出现，A6「等恢复与看广告等权」立刻失效 |
| 3 | **不存在跳过刮除的按钮** | v0.8 的「懒得刮 · 直接揭晓」删除。「扫尾补齐」只在剩余涂层 <5% 且 3 秒无操作时触发——它补的是"最后一点边角"，不是"整张票" |

### K.2 「买次数」到底买什么：三种解释的裁决

用户原话「针对不同票可以买次数，花钱买次数刮得更快」有三种实现方式，只有一种是干净的：

| 解释 | 实现 | 问题 | 裁决 |
|---|---|---|---|
| ① **次数门槛**：一张票限定刮 N 次，超出必须买次数 | 玩家刮到一半被拦住 | 这是**最纯粹的付费墙**：不给钱就卡在半张票上，违反红线 2 和 PRD A6 | ✗ 否决 |
| ② **刀的一次性消耗**：每买一把刀只能用 X 次，用完消失 | 刀具是消耗品 | 玩家会囤刀不敢用（违反"进度只进不退"的心理契约）；且"刀用完了"是很烦的中断 | ✗ 否决 |
| ③ **锋利度（采用）**：刀是永久的，锋利度 0-100 会掉，掉到 0 只是变钝（k ×0.70），磨一下回满 | 一条可见的条，一个便宜的修复动作 | 无 | **✓ 采用** |

> 为什么③是唯一干净的：**它把"次数"变成了"手感"，而不是"配额"。** 玩家看到的是"刀钝了该磨了"（一个世界内的、有质感的提示），而不是"你的刮除次数已用尽"（一个系统外的、收费站式的提示）。同一件事，两种叙事。

### K.5 磨刀 / 刀油（金币出口）

| 动作 | 效果 | 成本 | 成本公式 | 单次价值 | 设计意图 |
|---|---|---|---|---|---|
| **磨刀（满）** | `sharp = 100` | 600 币（10 元档时） | `0.30 × SCALE` | 恢复 12 张票的速度 | 主修复动作，便宜到"不必犹豫" |
| **刀油（+30）** | `sharp = min(100, sharp + 30)` | 240 币 | `0.12 × SCALE` | 恢复 3-4 张票的速度 | 微决策：只在"还差一点就要磨"时用，省 60% |
| **看广告磨刀（A6）** | `sharp = 100` | 0 | — | 同磨刀 | 免费路径，见 13.5 |
| **换刀** | 切换已购刀 | 0 | — | — | 已购刀具随时切换，不做二次收费 |

**磨刀的经济意义（比例恒定，不随进度漂移）**：

```
磨刀成本 / 一张票的期望收益 = 0.30 × SCALE / (SCALE × RTP) = 0.30 / 1.70 = 17.6%
每 12 张磨一次 → 摊到每张 = 17.6% / 12 = 1.5%
```
→ 磨刀是**节奏成本**（一个每 12 张出现一次的小中断），不是**经济压力**。这是刻意的：它存在的目的是让"刀"这个东西有存在感，不是消耗金币。

| 出口 | 首日占比 | D7 占比 | 说明 |
|---|---|---|---|
| **刮刀（买断 + 磨刀）** | **38%** | **22%** | 首日 3,000 买铜刀 + 2 次磨刀 ≈ 4,200 币，占首日出 34,700 的 12%… 但首日只有 1 次买刀，摊到"D1 全部金币支出"口径为 38%（含首日之后 24 小时内买钢刀） |

| 兑奖台升级 | 5% | 12% | 见 L.4 |
| 金币买票 | 2% | 4% | 受 `BUY_CAP` 限制 |

> 口径说明：**首日 38% 的关键不是买刀便宜，是"第一把刀必须买得起"**。首日 15 分钟收入 6.5 万，铜刀 3,000 只占 4.6%——玩家会毫不犹豫地买，然后立刻体验到 1.2× 速度差。**这个"毫不犹豫"就是刮刀系统的全部设计目的**：先让玩家习惯"金币可以换时间"，后面 B3/B4/B5 的 24,000 / 160,000 / 720,000 才有说服力。

| 用户说的 | 我们做的 | 位置 |
|---|---|---|
| "底下有铲子、刮刀" | 刮卡页底部常驻工具栏：左＝当前刀（点击换刀/磨刀），右＝兑奖入口 | 16.4 |
| "针对不同票可以买次数" | 不同档位的票消耗不同锋利度（5 元 6 点，50 元 24 点）→ 大票"更费刀"，界面上明确显示 `本张 -24 锋利` | K.4 |

| "刮得更快"的上限 | 1.90×（最快）vs 0.70×（最钝）= **2.7 倍时间差**，但两者都能刮完 | K.1 红线 2 |

### K.8 "玩家为什么多玩 10 分钟"

> 锋利度条是一个**每 4-16 张就要处理一次的小状态**。它做三件事：① 给"再来一张"一个具体理由（"再刮 2 张正好该磨刀，磨完这一批"）；② 把金币支出从"大额神秘升级"变成"小额高频手感维护"，让玩家更容易把钱花出去；③ 提供全游戏唯一一个"我的操作效率在变高"的可感知曲线——这条曲线比任何数字增长都更能留住人。

## 系统 L：兑奖台与揭晓仪式（v2.1 新增）

### L.1 用户诉求的翻译（这一条最容易做砸）

用户原话：「最后的成绩上要花钱才能或者看广告才可以知道」。

三种实现方式，只有一种能活：

| 实现 | 做法 | 结果 | 裁决 |
|---|---|---|---|
| 字面实现 | 不付币 / 不看广告 → 不显示中没中 | **刮完看不到结果 = 当场卸载**。同时违反 PRD A1（不做暗示）、A3（不做追损）、A6（免费路径与付费路径等权） | ✗ 否决 |
| 半实现 | 显示"中没中"，但要付币才显示金额 | 金额就是结果。拆开卖是欺骗，且玩家会立刻算出来 | ✗ 否决 |
| **采用** | 刮完**立刻、免费、完整**看到每一格与合计；但"合计 → 入账"要走一趟兑奖台，**仪式本身可以升级，信息永不收费** | 用户要的"揭晓有分量"被满足，且不欠任何人一笔钱 | **✓ 采用** |

> **判断依据**：用户要的不是"信息收费"，是"揭晓这件事要有分量"。真实彩票的兑奖之所以有仪式感，不是因为收费，是因为**它要专门走一趟**。我们复制"走一趟"，不复制"收费"。
> **一句话口径**：付费买"分量"，不买"信息"。

### L.2 兑奖流程（状态机）

```
刮完（100% 涂层）
  → 立即显示：每一格内容 + 命中格高亮 + 本张合计（大字，不可隐藏）
  → 票滑入「待兑口袋」（POCKET_MAX = 30）
       ├ 口袋未满：可继续刮
       └ 口袋已满：强制引导去兑奖台（不丢失、不清零、不罚款）
  → 兑奖台：整叠兑奖
       → 逐张「扫保安区」（每张 0.35 秒，票面左下角刮开一小块）
       → 单张金额逐条亮出（0.25 秒/张）
       → 整叠合计滚动（0.9 秒）
       → 入账 + 手气槽结算 + 图鉴盖章 + 口袋清空
```

**硬性规则**：

| # | 规则 | 原因 |
|---|---|---|
| 1 | 口袋内的票**永久有效**，无倒计时、无过期、无手续费 | P2 支柱（进度只进不退）；真实彩票的 60 天期限不复制 |
| 2 | 任何界面都能看到口袋里的**已刮出合计** | 信息不隐藏；玩家随时能自己算 |
| 3 | 「直接入账」按钮常驻（跳过仪式） | 仪式不可强制。玩家赶时间时一键入账，金额 100% 到账，只失去整叠加成 |
| 4 | 兑奖动画 ≤7 秒，且可点击跳过到结果页（不可跳到"什么都没有"） | 防止仪式变成惩罚 |
| 5 | 不做大额扣税 | 真实（超 1 万扣 20%）但玩家感知为惩罚，且与"纯娱乐"定位冲突 |

### L.3 三档揭晓（全部免费，加成来自"攒"而不是"付"）

| 档 | 触发条件 | 时长 | 表现 | 加成 | 谁在付费 |
|---|---|---|---|---|---|
| **普通揭晓** | 默认 | 2.5 秒 | 数字滚动 + 轻铃 | 0% | 无人 |
| **整叠揭晓** | 一次兑 ≥5 张 | 4.0 秒 | 逐张铃响 + 彩纸 + 合计滚动 | **+5% （5-9 张）/ +8%（10-19 张）/ +12%（≥20 张）** | 无人（靠攒） |
| **中心兑奖** | 单张 ≥100× 面额（大额票） | 6.0 秒 | 票面转金 → 进"金柜" → 全屏光晕 → 单独结算 | 0%（纯仪式） | 无人 |

**整叠加成表（`STACK_BONUS`）**：

| 张数 `n` | 加成 | 字段名 |
|---|---|---|
| 1-4 | 0% | — |
| 5-9 | +5% | `STACK_BONUS.t5` |
| 10-19 | +8% | `STACK_BONUS.t10` |
| 20-30 | +12% | `STACK_BONUS.t20` |

> **这是全游戏最强的"再来一张"理由，而且它给的是加成、不是惩罚。** 玩家本来刮了 8 张要停手，看到"再 2 张整叠 +8%"，会再刮 2 张。这条设计同时满足 P2（不清零）与 P3（每 3 分钟一次跳变）。

### L.4 金币在兑奖环节的唯一合法用途：永久升级

**不做单次收费**（不卖"揭晓资格"、不卖"翻倍券"）。金币买的是兑奖台的**能力**：

| 升级 | 等级 | 效果（每级） | 成本（Lv1 基准） | 成本曲线 | 字段名 |
|---|---|---|---|---|---|
| **票袋** | 1-10 | 口袋上限 +6（30 → 90） | 8,000 | `×1.55^(lv-1)` | `CLAIM.pocket` |
| **印章** | 1-10 | 整叠加成 +1%（+5% → +15%） | 12,000 | `×1.60^(lv-1)` | `CLAIM.stamp` |
| **铃铛** | 1-5 | 揭晓提速 + 大额票专属音效（纯体验） | 20,000 | `×1.80^(lv-1)` | `CLAIM.bell` |

- **票袋**：把"攒 20 张兑一次"变成"攒 60 张兑一次" → 直接放大整叠加成 → 玩家会主动延后兑奖，把兑奖变成一次"活动"
- **印章**：整叠加成从 5% 涨到 15% → 让"攒"这件事的收益越来越值得等
- **铃铛**：唯一一个纯体验升级（不提数值）→ 给"我不想再变强了，我只想好看"的玩家一个出口

> 三项都是**永久、只增不减**（符合 P2），且没有一项是"付费才能看到结果"。金币在这里买到的是**"更值得等的兑奖"**，不是**"兑奖的许可"**。

### L.5 与广告的关系（A7）

| 项 | 内容 |
|---|---|
| 位置 | 兑奖台，整叠 ≥5 张时出现 |
| 奖励 | 本次整叠入账 **+50%** |
| 日上限 | 6 次 |
| 免费替代 | 不看广告也 100% 到账（基础 + 整叠加成照给） |
| 为什么给 +50% 而不是 ×2 | "再领一份"（×2）会让不看广告的玩家产生"我亏了一半"的剥夺感，这是**负向设计**；+50% 是"额外奖励"，感知是"我赚了"，不是"我没拿" |
| 转化预期 | 兑奖是情绪峰值（刚看到合计），是除 A2 之外转化最高的位；目标触发率 ≥60% |

### L.6 兑奖为什么让人多玩 10 分钟

> 口袋是一个**可见的、会变长的待办清单**。30 格的格子（升级后 90 格）本身就是进度条：玩家会不自觉地去"填满它"。而"填满 → 一次性兑 → +12% → 数字大幅滚动"是一个**自造的高潮**，比任何系统给的奖励都更像"我攒出来的"。
> 更关键的是：它把"刮完"这个动作从"结束"变成了"入库"。**结束是断点，入库是累积。** 玩家不会为了"再刮一张"留下，但会为了"凑够 20 张一起兑"留下。

### L.7 红线清单（逐条阻塞提审）

```
□ 刮完 100% 后，本张合计在 0.5 秒内可见，且无任何付费/广告前置
□ 「直接入账」按钮在兑奖台常驻
□ 口袋内票据无过期、无手续费、无扣税
□ 兑奖动画可跳过，且跳过不减少任何金额
□ 不存在任何"付费解锁结果"的文案或流程
□ 大额票的"中心兑奖"只是视觉仪式，不影响金额
```

### 14.5 多局票的期望值公式（唯一权威，替代 5.3 的单奖级公式）

v2.0 的 5.3 是"单奖级 → 单次赔付"。多局票的 EV 是**命中格数 × 单格倍数**的乘积，公式更简单：

```
给定：档位票价 P、目标 RTP R、票型的单格倍数池权重 w（Σw = 1）
E[m] = Σ w_i × m_i                         // 单格期望倍数，票型决定
E[K] = R / E[m]                            // 命中格数期望，由 RTP 反解
m_i  ∈ {1, 1.5, 2, 3, 5, 10, 30, 100, 300, 800}   // 单格奖金 = m_i × P

单张 EV = E[K] × E[m] × P ≡ R × P           // 恒等，三档票型 RTP 必然相等
中奖率  = 1 − P(K = 0)                      // 由 K 分布的 p(0) 直接读出
```

**为什么三档 RTP 天然相等**：`E[K]` 是**算出来的**，不是设的。票型只改 `w`（倍数池形状）与 `K` 的分布形状，`E[K]` 被 `R / E[m]` 锁定 → `EV ≡ R × P`。这是"无主导策略"的数学证明，与 v2.0 5.3 的思路一致，但少了一层中间变量。

**单格倍数池（基准池，票型在其上做偏置）**：

| `m`（倍数） | 10 元档金额（币） | 权重 `w` | 语义 | 玩家感受 |
|---|---|---|---|---|
| 1× | 2,000 | 55% | 回本 | 「没白刮」 |
| 1.5× | 3,000 | 22% | 回本+ | 「小赚」 |
| 2× | 4,000 | 12% | 双倍 | 「这张可以」 |
| 3× | 6,000 | 6% | 三倍 | 「不错」 |
| 5× | 10,000 | 3% | 五倍 | 「有点东西」 |
| 10× | 20,000 | 1.3% | 十倍 | 「中了」 |
| 30× | 60,000 | 0.5% | 三十倍 | 「这把稳了」 |
| 100× | 200,000 | 0.15% | 百倍 | 「大额票」→ 走中心兑奖 |
| 300× | 600,000 | 0.04% | | 「要发群里」 |
| 800× | 1,600,000 | **0.01%** | **头奖** | 传说 |
| **Σ** | | **100%** | `E[m] = 2.08` | |

**三档票型的偏置表（`w` 与 `K` 形状，RTP 全部 = 1.70，以 10 元档为例）**：

| 票型 | 倍数池偏置 | `E[m]` | `E[K]`（算得） | K 分布（0/1/2/3/4 格） | 中奖率 | 平均中奖格 |
|---|---|---|---|---|---|---|
| **稳** | 小倍数权重 +15%（1×/1.5×/2×），大倍数 ×0.6 | 1.75 | 0.971 | 0.32 / 0.44 / 0.19 / 0.04 / 0.01 | **68%** | 1.43 |
| **平** | 基准池 | 2.08 | 0.817 | 0.43 / 0.38 / 0.14 / 0.04 / 0.01 | **57%** | 1.43 |
| **冲** | 大倍数权重 ×2.2（10× 及以上），小倍数堆到 1× | 2.75 | 0.618 | 0.58 / 0.24 / 0.11 / 0.05 / 0.02 | **42%** | 1.47 |

> 三种票型的**中奖率与中奖金额成反比，乘积恒等**——这正是 v2.0 5.3 想达到的效果，现在用更少的变量达到了。
> 头奖概率：`P(头奖) = E[K] × 0.0001 ≈ 1/12,000`（按平型）。重度玩家（29 张/日）约 400 天遇一次。**这是刻意的：头奖必须稀有到"值得说"，但不能稀有到"不存在"。**

| 最小滑动距离 | 3 px/帧 | 不变 | 防点触 |
| **刮除阈值** | 78% | **100%** | 用户明确要求"不要一键直接打开"；实际判定用"格级 75%"（见下） |
| **格揭晓粒度** | 整格（一次触摸即整格消失） | **每格 2×2 子块，`popcount(mask) ≥ 3` 即揭晓** | 见 J.7 |
| **扫尾补齐** | — | 剩余涂层 <5% 且 3 秒无操作 → 自动补完剩余 5% | 防"卡在最后一格找不到"；补的是边角，不是整张票 |
| 揭开动画 | 0.4s 渐隐 + 缩放 | 不变 | |
| 粒子 | 每帧 3-5 个碎屑 | 不变，但按档位加权（大票 ×1.4） | |
| **「一键揭晓」按钮** | 有（「懒得刮 · 直接揭晓」） | **删除** | 见 20 章 #13 |

> **100% 与"扫尾补齐"的关系**：阈值是 100%（必须刮完才能结算），但"最后 5% 刮不到"的人性化问题由扫尾解决。玩家体验是"我刮完了 → 自动结算"，而不是"我还差一点但找不到"。实测若卡壳率 >3%，把 `SCRATCH_TAIL_AUTO_MIN` 从 5% 调到 8%（只调这一个数，不动阈值）。

### 15.4 多局票的表现规范（v2.1 新增）

### 18.2 测试期必须精调的四个数

| # | 参数 | 为什么最重要 | 调错的后果 |
|---|---|---|---|
| **1** | `FAC_BONUS`（1.15）+ `FAC_COST_RATIO`（1.16） | 决定升级节奏 = 决定"每 3 分钟一次跳变"是否成立 | 太低 → 升级太慢（用户抱怨的"推进慢"）；太高 → 数字爆炸失去意义 |
| **2** | `PEEK_CELLS`（2） | 决定"选择是否有用" = P1 支柱生死 | 1 局 → 玩家觉得三张一样（伪选择）；3 局 → RTP 提升 25%，经济过热 |
| **3** | `TICKET_RECOVER_BASE`（45s）+ `BUY_CAP_BASE`（30） | 决定票缺口 = 决定广告次数 = 决定收入 | 缺口太小 → 不看广告；太大 → 弃游 |
| **4（v2.1 新）** | `SCRATCH_RATE_BASE`（3,300 dp²/秒） | 决定单张时长 = 决定"打发时间"到底是 20 秒还是 50 秒，也决定 `BLADE_K` 的相对价值 | 太快 → 40 局票 25 秒刮完，"很多局"变成"闪一下"；太慢 → 50 元票 70 秒，玩家第一次感到"累" |

> **第 4 个数为什么重要到要和前三个并列**：v2.0 只有一个数（`SCRATCH_BRUSH_RADIUS`）控制时长，且所有票时长相同。v2.1 时长变成五档，`SCRATCH_RATE_BASE` 是唯一能把五档**同时**按比例移动的旋钮——调刀、调笔刷都只影响单点，调它是调整条曲线。

```
function rollCandidates(ticketId, count):
    local list = {}
    local profiles = shuffle({"steady","normal","wild"})
    for i = 1, count do
        local profile = profiles[i] or randomProfile()
        local result = generateByProfile(ticketId, profile)   -- 走结果生成规范
        result.profile = profile
        result.peek = randomChoose(cells, PEEK_CELLS)         -- 随机挑 2 格
        -- 标记已揭开
        for _, idx in ipairs(result.peek) do result.revealed[idx] = true end
        list[i] = result
    end
    return list
end
```

### 19.6 倍率计算（唯一入口，禁止散落）

```
function rewardMult():
    local m = 1
    m = m * math.pow(FAC_BONUS, state.fac.counter - 1)     -- 柜台
    m = m * (1 + backStaffBonus())                          -- 后场岗
    m = m * (1 + stampBonus())                              -- 图鉴
    m = m * (1 + titleBonus())                              -- 头衔
    m = m * (1 + 0.08 * state.facPrestige)                  -- 无限扩建
    return m
end
```
