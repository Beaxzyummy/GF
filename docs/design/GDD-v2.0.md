## 1. 设计支柱

### 1.1 三条支柱

| # | 支柱 | 一句话 | 判定问题（答"否"=违规） |
|---|---|---|---|
| **P1** | 判断优先于运气 | 每 20 秒必须有一次"我看准了" | 玩家这一张票的选择，是否改变了他可能拿到的东西？ |
| **P2** | 进度只进不退 | 没有任何东西会因为时间或失败而变少 | 是否存在清零/衰减/断签扣减？ |
| **P3** | 每三分钟一次跳变 | 数字必须"跳"，不能"爬" | 3 分钟内是否至少一次升级/解锁/大额入账/券到手？ |

### 1.2 支柱的自洽性检查（防支柱打架）

| 冲突可能 | 原因 | 化解规则 |
|---|---|---|
| P1 vs 主导策略 | 三种票型若 RTP 不等，最优解唯一 → 选择退化为"永远选那个" | **三档 RTP 必须完全相等**（5.4 已验证：6 票 × 3 档两两差 <0.01） |
| P2 vs 无限囤积 | 进度不清零 → 玩家可以永远囤运势券不用 | 券上限 2 张，满则必须用掉才能再攒 |
| P3 vs 通胀失控 | 跳变靠倍率 → 倍率爆炸 → 数字失去意义 | 设施成本按"3 分钟收入"阶梯设定（11.3）；`FAC_BONUS` 是唯一通胀阀门 |
| P3 vs 广告缺口 | 跳变太爽 → 玩家不缺票 → 不看广告 | 跳变发生在"金币/设施"轴，票始终是独立闸门（14.2） |

### 1.3 支柱漂移的红旗（评审时逐条查）

| 红旗 | 表现 | 处置 |
|---|---|---|
| 三选一变成"选最贵的" | 票型被忽略，只看面额 | 三档 RTP 审计 |
| 手气槽变成"进度条挂机" | 玩家不看屏幕只等槽满 | 槽只在刮开时 +4，不看广告不给槽 |
| 元游戏变成"数字模拟器" | 升级只有数字变化，没有玩法变化 | 每 5 级必须解锁一个"新东西"（见 11.5） |
| 副循环重新抢戏 | 转盘/广告单次收益 > 3 张票 | G3 门禁脚本校验（PRD 10.1） |

## 2. 诊断 → 解法映射（MDA）

### 2.1 问题清单与对应机制

| 诊断（PRD 一章） | MDA 层 | 缺失的美学 | v2.0 解法 | 为什么能解决 |
|---|---|---|---|---|
| D1 无决策 | Mechanics | Challenge | **三选一 + 预揭格** | 把"买"变成"判断"；信息不完备 → 每次判断都不同 |
| D2 无期待 | Dynamics | Fantasy / Narrative | **手气槽 + 运势券 + 悬赏** | 给"下一次"一个确定的、可视的承诺 |
| D3 数值失序 | Mechanics | — | **SCALE 缩放体系 + 主干优先律** | 所有固定奖励改为"以当前面额为基准" |
| D4 一次一大步失败 | Dynamics | Sensation | **面额 ×20 重定标 + 阶梯成本表** | 首日即万级数字；每 3 分钟一次升级 |
| D5 元游戏缺位 | Mechanics | Expression | **4 设施 + 3 岗位 + 无限扩建** | 金币有永久出口；员工从"产币"改为"产票/加乘" |
| D6 首个 60 秒 | Dynamics | — | **预置槽值 + 必中邀请票 + 无文字引导** | 60 秒内 2 次中奖 + 1 次跳变 |

### 2.2 主干优先律（数值宪法）

> **任一时刻，核心循环（刮卡）的金币/分钟 ≥ 全部副循环（转盘 + 广告 + 悬赏 + 离线）之和 × 3。**

v0.8 违反此律达 99:1，这是"不好玩"的第一结构性原因。v2.0 的检验脚本见 19.7。

| 循环 | v0.8 每分钟金币 | v2.0 D1 | v2.0 D7 | 占比（D1 / D7） |
|---|---|---|---|---|
| 刮卡（主） | 16.3 | 384 | 571,222 | **77% / 98.8%** |
| 转盘（副） | 1,210 | 110 | 6,612 | 22% / 1.1% |
| 悬赏（副，摊薄到分钟） | 0 | 6 | 375 | 1% / 0.06% |
| 离线（副） | 不定 | 不计入分钟（单独封顶） | 同左 | — |

> 计算口径：转盘 = `5.51 × SCALE ÷ 5 分钟`；悬赏 = `3 × 30 × SCALE ÷ 1440`。
> 结论：v0.8 主副比 0.013:1（副循环是主循环的 74 倍）；v2.0 D1 为 3.3:1、D7 为 81:1，全部 ≥3 ✓。
> 副循环在 D1（票最紧时）仍有 22% 的存在感，正是"票用完还有事做"的设计意图；随刮卡收入放大自然退位。

## 3. 理论工具箱

### 3.1 自我决定论映射

| 需求 | 机制 | 强度设计（可调） |
|---|---|---|
| 自主 | 3 选 1 票 / 稳平冲 / 券给谁用 / 设施顺序 / 排班 | 候选数 `PEEK_CANDIDATES`（默认 3，可降 2） |
| 胜任 | 预揭信息可学习；熟练玩家 RTP +8~12% | `PEEK_CELLS`（默认 2，可升 3） |
| 关联 | 22 员工性格 + 店招 + 头衔 | 员工文案量（22 条，见 17.4） |

### 3.2 可变比率强化（Variable Ratio）的正确用法

刮刮乐天然是 VR 强化（不知道第几次中），但**纯 VR 会衰减**（老虎机的衰减曲线是所有赌博机制里最陡的）。v2.0 用**双层结构**对抗衰减：

| 层 | 机制 | 强化类型 | 作用 |
|---|---|---|---|
| 外层 | 三档奖级表（中奖率 3%~62%） | 可变比率 | 提供不可预测的惊喜 |
| 内层 | 手气槽每 10 张必给 1 张券 | **固定比率（FR-10）** | 提供可预测的确定性 |

> 只给 VR → 玩家算不清账，挫败；只给 FR → 无聊。**VR 外套 FR** = 惊喜有底，努力有价。

### 3.3 心流平衡表（挑战 vs 技能）

刮刮乐没有"技能门槛"，所以心流靠**决策难度**而非操作难度调节：

| 阶段 | 决策复杂度 | 认知负荷 | 心流风险 | 对策 |
|---|---|---|---|---|
| D1（0-15 分钟） | 1 个决策（选哪张），信息 2 格 | 低 | 无聊 | 强制出"明显更好"的那张（预揭含 ×10） |
| D3 | 3 个决策（选票/用券/升级谁） | 中 | 心流区 | — |
| D7 | 5 个决策（+排班 +抽卡规划） | 中高 | 焦虑 | 所有决策都有"推荐"高亮，可一键采纳 |
| D30 | 5 个决策 + 长线规划 | 高 | 焦虑 | 无限扩建只给数字，不给新规则（不再加认知） |

> **认知红线**：一级界面上同时可见的"可决策元素"≤ 3 个。超过就折叠。

### 3.4 损失厌恶的反向使用

| 传统博彩 | 机制原理 | 我们的反向用法 | 代码落点 |
|---|---|---|---|
| 输了想赢回 | 损失厌恶 | 不存在"输掉已有资产" | 无任何扣减逻辑（P2） |
| 差一点中 | near-miss 错觉 | 用"预揭 2 格"给**真实**信息 | `peekCells` |
| 限时逼单 | 稀缺焦虑 | 用"确定性倒计时"给安心 | `luckGauge` 显示"再 N 张" |
| 沉没成本 | 投入越多越难走 | 用"资产越攒越舍不得" | 图鉴/设施/头衔 |

## 4. 四层循环

### 4.1 总图

```
[30 秒] 单张票
  看 3 张候选（各露 2 格）→ 选 1 张 → 刮 → 开奖 → 槽 +4
        ↓ 累积 8-10 张
[3 分钟] 一轮
  槽满 → 运势券 → 券给谁 → 设施升级 → 票种进度 +N
        ↓ 累积 3-4 轮
[15 分钟] 一次会话
  补票广告 / 十连 / 排班 / 悬赏结算 / 离线计时开始
        ↓ 累积 1 天
[跨天] 回访
  签到 / 悬赏刷新 / 连登解锁 / 离线收益 / 周悬赏
```

### 4.2 逐层拆解（决策点 → 反馈 → 下一步）

#### 第 1 层：30 秒（单张票）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | 3 张候选中选 1 张。依据：①预揭的 2 格内容 ②票型（稳/平/冲）③运势券是否要用 | 每分钟 2-3 次决策，全部是"一眼可判"的低负荷判断 |
| **反馈** | 刮除手感（三层阻力）→ 匹配格逐格点亮（音阶递进）→ 奖级 → 金币滚动 → 手气槽 +4 的动画 | "我选对了"的即时确认 |
| **下一步** | 槽进度条显示"再 6 张有运势券"；或"这张特等奖已盖章（图鉴 3/4）" | 每一次结算都留下一个未完成的承诺 |

> **决策密度校准**：单张 25 秒 → 2.4 张/分钟 → 每分钟 2.4 次选票决策 + 0.4 次"用不用券"决策 ≈ **2.8 次/分钟**，满足 PRD 的 ≥2 次门禁。

#### 第 2 层：3 分钟（一轮 6-8 张）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①运势券用在哪种票上（存还是用）②金币升级哪个设施（4 选 1）③继续买票还是去转盘 | 从"判断"升级到"配置"，产生策略感 |
| **反馈** | 设施升级后立刻可见的数值跳变（"柜台 Lv5：单张奖金 +15%"）；券打出的大额入账（≥ 面额 5 倍） | **P3 支柱的落点**：每 3 分钟一次跳变 |
| **下一步** | 结算页只显示一个引导：「再刮 6 张解锁「烫金」」或「升级柜台需 13,000 币，还差 2,100」 | 单一引导，不做并列选项（防选择过载） |

#### 第 3 层：15 分钟（一次会话）

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①票不够：等 2:47 还是看广告（等权按钮）②有 1,600 钻：单抽还是攒十连 ③员工排班：柜台还是后场 | 3 个决策都属于"资源配置"，时长 15 分钟内自然发生 |
| **反馈** | 悬赏完成弹出（带实物感奖励）；抽卡动画分级；离线计时开始（显示"8 小时后回来可得 N 张票"） | 会话末段给"关掉的理由"+"回来的理由" |
| **下一步** | 离线面板预告：`离店 8 小时 → 票 +N、金币 +N` | 把"下次什么时候来"写死成数字 |

#### 第 4 层：跨天

| 环节 | 内容 | 设计意图 |
|---|---|---|
| **决策点** | ①签到选第几档（连续奖励递增）②周悬赏的目标票种 ③无限扩建投哪个设施 | 低频高权重决策 |
| **反馈** | 头衔晋升全屏仪式；图鉴完成度；连登天数 | 身份感（SDT 关联） |
| **下一步** | 连登 3 天解锁「霜花」（D3 核心钩子）；周悬赏倒计时"还剩 3 天" | D1/D3/D7 的具体回访理由见 12.5 |

### 4.3 首个 60 秒（分秒脚本）

> 目标：60 秒内完成"2 次中奖 + 1 次跳变 + 理解 3 个系统"，且**全程没有一句教学文字超过 12 个字**。

| 时间 | 屏幕 | 系统动作 | 设计原理 |
|---|---|---|---|
| 0.0-3.0s | 声明页（唯一可跳过项：一键"我已了解"） | 写 `first_launch`，生成存档 | 合规 + 先给确定性 |
| 3.0-6.0s | 柜台页，3 张候选票依次入场（0.08s 延迟） | `rollCandidates("T1")`，但第 1 张走 `rollFirstTicket()`：固定二等奖（匹配数 5），预揭 2 格均为匹配符号「福」 | 第一眼就有"可判断的信息" |
| 6.0-9.0s | 第 1 张票上浮 6px（呼吸动画），其余两张压暗 20% | 只高亮 1 张，不强制 | 视觉引导代替文字 |
| 9.0-12.0s | 手指虚影划一下（1.5s 循环） | 首张笔刷半径 ×1.4（40 → 56） | 降低第一次操作挫败 |
| 12.0-30.0s | 刮除 → 78% 自动揭开 | 逐格点亮，音阶从低到高 | 刮感第一次建立 |
| 30.0-33.0s | 结算：二等奖 + 500 币 | 中奖四档反馈里的"二等奖"档（1.4s） | 首张必中，固定二等奖 |
| 33.0-38.0s | 手气槽 32/40（预置值），文案"再 2 张，有张运势券" | `luckGauge = 32` 写死 | 立刻给出一个 2 步可达的终点 |
| 38.0-48.0s | 自动回到柜台（0.4s 静默），3 张新候选，其中一张（稳型）预揭露出 2 个「福」，另一张露出「福」+「禄」（对不上） | 第 2 张候选保证预揭"好看" | 让玩家自己发现"要看预揭" |
| 48.0-60.0s | 玩家选中 → 刮开（命中）→ 槽 36→40 → **运势券到手** → 引导"柜台升 Lv.2 需 1,000 币"（差额补足） | `vouchers = 1`；补足金币让第一次升级可达 | 第 60 秒完成第一次"跳变"（P3 支柱） |

**三个硬约束**：

| # | 约束 | 原因 |
|---|---|---|
| 1 | 首张票必中（固定二等奖），且公示页注明"新手首张为引导票" | 首次体验必须正向；公示保证合规 |
| 2 | 手气槽预置 32，第 2 张即满 | 60 秒内必须让玩家看到"券"这个长期机制的实物 |
| 3 | 首次升级的差额由系统补足（最多补 1,000 币） | 让"升级"这件事在第 1 分钟就被学会；只发生一次 |

> 无弹窗、无箭头遮罩、无"下一步"按钮。引导只用三样东西：**高亮、虚影手指、进度条**。

### 4.4 层与层之间的"下一步诱惑"（一屏只能有一个）

| 当前层结束于 | 唯一显示的下一步 | 为什么是这个 |
|---|---|---|
| 单张结算 | 槽进度 / 图鉴盖章 / 票种进度（三选一，按优先级） | 优先级：槽 > 票种 > 图鉴（槽最近可达） |
| 一轮结束 | 设施升级卡（可负担时）/ 票种解锁（差 ≤10 张时） | 跳变优先 |
| 会话结束 | 离线收益预告 | 把"关掉"变成"投资" |
| 跨天开始 | 签到 + 离线收益 | 先给后要 |

## 5. 系统 A：柜台三选一（核心机制）

### 5.1 这是什么

把 v0.8 的「点票种 → 直接买 → 刮」改成「进柜台 → 系统给 3 张同面额、不同票型的候选票（各预揭 2 格）→ 你选 1 张 → 刮」。

**唯一目的**：在不改随机数、不改合规边界的前提下，造出每秒都在发生的真实决策。

### 5.2 候选票生成

```
生成时机：每次进入柜台页（或点"换一批"）
生成数量：3 张（PEEK_CANDIDATES）
票型分配：稳 / 平 / 冲 各 1 张（顺序随机打乱）
面额：当前选中的票种面额（三张同面额、同价格）
预揭：每张随机挑 2 格揭开（福彩 = 9 格中的 2 格；M10 = 10 注中的 2 注）
```

**关键约束（不可妥协）**：

| 约束 | 说明 |
|---|---|
| 三张票各自独立走「先抽奖级、再倒填符号」流程 | 遵守 `docs/结果生成规范.md`；预揭格是**该票真实结果的子集**，不是伪造 |
| 三档 RTP 完全相等 | 见 5.4；差 >0.01 即出现主导策略 |
| 预揭格随机取样，不偏袒 | 不许"为了让玩家选中而挑好看的格子"（除首张引导票，见 4.3） |
| 未选中的 2 张作废 | 不保留、不回收；防止无限刷候选（也不能"换一批"刷到满意——换一批有冷却 30 秒且重置手气槽进度 0） |

### 5.3 三种票型（稳 / 平 / 冲）

三张票**同一价格、同一面额、同一 RTP**，只在"奖级配比"上不同：

| 票型 | 名称 | share 向量（三等奖/二等奖/一等奖/特等奖） | 中奖率（T1） | 玩家感知 |
|---|---|---|---|---|
| `steady` | **稳** | 0.86 / 0.12 / 0.018 / 0.002 | 62.1% | 「常有小惊喜」——新手默认高亮 |
| `normal` | **平** | 0.62 / 0.28 / 0.09 / 0.01 | 29.7% | 「正常手感」 |
| `wild` | **冲** | 0.30 / 0.40 / 0.24 / 0.06 | 11.0% | 「一把见分晓」——特等奖概率是稳的 33 倍 |

**概率解算公式（这是 18 张表的唯一来源）**：

```
给定：面额 P、目标 RTP R、赔付向量 v = [v3, v5, v7, v9]
     票型 share = [s3, s5, s7, s9]（Σs = 1）

中奖率 W = (R × P) / Σ(s_j × v_j)
p_j     = s_j × W          （j = 3/5/7/9）
p_0     = 1 − W
```

> 数学性质：因为 W 被分母归一化，`Σp_j × v_j ≡ R × P`，**三档 RTP 恒等**。这是"无主导策略"的数学证明，不是调试结果。

### 5.6 预揭格（PEEK）——整个 v2.0 的支点

**规则**：每张候选票在购买前，随机挑 `PEEK_CELLS = 2` 格揭开，永久可见（购买后这 2 格已算刮开，计入 78% 进度）。

| 票种 | 预揭内容 | 例子 |
|---|---|---|
| 福彩 6 票 | 2 格符号 | 「这张露出：福、福」→ 已锁定 2 个匹配，至少是三等奖 |
| 好运十倍 | 2 注的号码 + 奖金 + 是否 ×10 | 「第 3 注：号码 17（对照号 17）奖金 300 ×10」→ 已被锁 3,000 |
| HOT 全收 | 3 格金额（不揭 HOT 位） | 「400 / 12,000 / 4,000」 |

**为什么这不破坏概率**：预揭是结果生成后"提前揭开"的格子，不参与随机决策 → 每张票的边缘分布不变，公示表仍然准确。

**已知副作用（必须承认并调参）**：玩家会挑"露得好的"那张，于是**实际 RTP 高于公示的每票 RTP 约 +8~12%**。

| 处理 | 说明 |
|---|---|
| 定性 | 视为**特性**（奖励判断力），不是 bug。这是"选择有用"的证明，也是 P1 支柱的量化落点 |
| 监控 | 埋点 `choice_regret`（选中票 vs 未选中票的收益差）。若差值 <5%，说明预揭无信息价值，需加到 3 格 |
| 阀门 | `PEEK_CELLS` 2 → 1 可把选择增益砍半；经济过热时优先动这个，不要动 RTP 表 |
| 合规 | 公示页加一行：「每张票的 2 格在购买前即已揭开，选择不同票会影响你实际获得的平均回报。」——**说清楚比藏着安全** |

### 5.7 购买与配额

v0.8 的"有免费票用免费票，没票用金币买"保留，但**金币买票加日配额**——否则金币会绕过票闸门，广告位 A1 彻底失效（v1.1 模拟已证明 A1 对轻度玩家触发率为 0）。

| 支付方式 | 消耗 | 限制 |

| 运势券 | 不额外消耗 | 上限 2 张 |

> 配额用完后，按钮变「今日柜台已售完 · 明天再来」并给两个等权出口：「看广告 +20 票」/「等 2:47 自然恢复」。

## 6. 系统 B：手气槽与运势券

### 6.1 为什么是"固定值"而不是"未中才加"

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 未中 +3 / 中奖 +1 | 心理补偿强 | **造成主导策略**：冲型未中率 89% → 槽涨得快 3 倍 → 理性玩家永远选冲 | 否决 |
| 中奖才加 | 奖励准确 | 手气差时看不到希望，违背解压定位 | 否决 |
| **固定 +4/张** | 可预测、无套利、可承诺 | 惊喜感弱 | **采用** |

> 固定值还带来一个隐性收益：进度条变成"确定性倒计时"（"再 6 张"），比"概率性进度"更能驱动回访——这正是损失厌恶的反向使用（确定性替代焦虑）。

### 6.2 数值

| 参数 | 值 | 字段名 | 说明 |
|---|---|---|---|
| 每张增益 | +4 | `LUCK_GAIN_PER_TICKET` | 任何票种、任何票型都一样 |
| 槽容量 | 40 | `LUCK_CAP` | = 每 10 张出 1 张券 |
| 券上限 | 2 | `VOUCHER_MAX` | 满 2 张后槽不再累积（强制消耗） |
| 券保证档 | 匹配数 ≥ 5 | `VOUCHER_MATCH_GUARANTEE` | 即"二等奖及以上" |
| 跨天 | 不清零 | — | P2 支柱 |
| 跨票种 | 通用 | — | 防止"只玩一种票"的碎片化 |

### 6.3 运势券的三个决策点

| 决策 | 选项 | 为什么有意思 |
|---|---|---|
| 现在用还是存着 | 存（上限 2） | 面额越高，券的绝对值越大 → 天然鼓励"等解锁" |
| 用在哪张票型上 | 稳/平/冲 | 券只保证"≥二等奖"，在冲型上等于"用 5% 概率换 100% 命中"，在稳型上等于"用不上" → 明显应该配冲型，构成"稳→冲"的策略组合 |
| 用不用在 M10 上 | 是/否 | 券在 M10 = 保证至少 2 注命中（其中一注带 ×10 的概率另算）→ 可能一次给 4,000+ |

> **券 × 冲型** 是最优组合——这是设计好的"组合技"：手气槽负责提供确定性，冲型负责放大确定性。玩家自己发现这个组合时会觉得自己很聪明（胜任感）。

### 6.4 状态机

```
槽值 < 40       → 每刮完一张 +4，UI 显示 "手气槽 32/40 · 再 2 张有券"
槽值 = 40 且 券 < 2 → 券 +1，槽归零，播放"券入手"动画（0.8 秒）
槽值 = 40 且 券 = 2 → 槽停在 40/40，UI 提示"先用掉一张运势券"
用券刮票       → 结算时按保证档生成结果（走 5.5 表的下限重抽）
```

> **实现要点**：用券时不能"先抽奖级再看够不够"，而应该"从 ≥5 的档位里按原概率权重重抽"。重抽公式：`p'_j = p_j / (p5 + p7 + p9)`，抽完后公示表不变（因为这是券的效果，不是票的概率）。

## 7. 系统 C：好运十倍（旗舰玩法）

### 7.1 定位

### 7.4 生成算法（先定注数，再倒填）

```
function generateM10(profile):
    hitCount = weightedPick(hitsDist)           // 0/1/2/3
    winningNumber = randomInt(1, 40)
    entries = array(10)

    hitSlots = randomChoose(10, hitCount)       // 哪几注命中
    for i in 1..10:
        if i in hitSlots:
            number = winningNumber
            prize  = pick(pool)
            mult   = (random() < p10) and 10 or 1
        else:
            number = randomInt(1,40) excluding winningNumber
            prize  = pick(pool)                 // 不命中也要显示奖金，制造"差一点拿到"的视觉张力
            mult   = 1
        entries[i] = { number, prize, mult }

    // 预揭：随机挑 2 注标记为已揭开
    peek = randomChoose(10, 2)
    return { winningNumber, entries, peek }
```

**注意**：不命中的注也显示奖金（真票就这样）。这是视觉张力来源，但**不构成"差一点"暗示**——因为未中注的号码是随机生成的，与对照号无关联，且未中奖界面不给任何"就差一个"的提示（见 7.6）。

### 7.5 表现规范

| 时刻 | 表现 |
|---|---|
| 预揭注 | 已揭开的 2 注有 2px 金色描边 + 角标「已露」；其余 8 注覆银色涂层 |
| 刮开命中注 | 该注整注高亮 + 号码闪烁 2 次 + 单音「叮」 |
| 刮开 ×10 命中注 | 全屏短暂（0.15s）压暗 + 该注放大 1.2 倍 + 「×10」金漆质感 + 低音「咚」 |
| 结算 | 命中注按注数逐条累加（每注 0.25s），最后给合计 |
| 0 命中 | 0.4 秒静默 → 极轻的「沙」一声 → 自动回柜台，不做任何文字提示 |
| 多注命中 | 累计到第 3 条时追加一句「今天手气可以」（仅此一句） |

## 11. 系统 G：店铺经营（元游戏）

### 11.1 经营如何让"数字膨胀"有意义

数字膨胀本身是廉价的（改个乘数就行）。它有意义，靠三件事：

| 载体 | 玩家感知 | 数值落点 |
|---|---|---|
| **看得见的柜台** | 桌面 → 柜台 → 整层 → 一条街（4 个视觉阶段） | 柜台等级 1-10 / 11-20 / 21-29 / 30 |
| **单张票的收益翻倍** | "同样刮一张，现在给 3 倍" | 柜台 +15%/级 |
| **能刮的票变多** | "以前一天刮 40 张，现在 200 张" | 迎宾 + 员工柜台岗 |

> 一句话：**数字膨胀必须落在"我每一次动作的产出"上，而不是"我的仓库里有个大数字"。**

### 11.2 四个设施（v2.0 核心新增）

| 设施 | 效果（每级） | 上限 | 解锁 | 字段名 |
|---|---|---|---|---|
| **柜台** | 刮卡奖金 **×1.15**（复利） | 30 | 默认 | `FAC.counter` |
| **迎宾门** | 票恢复速度 +6%；票池上限 +15；金币买票配额 +2 | 30 | 默认 | `FAC.door` |
| **招财猫** | 员工产出 +6%（复利）；离线封顶 +0.25 小时 | 30 | 累计刮满 15 张 | `FAC.cat` |
| **转盘台** | 转盘金币 +15%；电上限 +1；电恢复 +4% | 30 | 累计刮满 15 张 | `FAC.wheel` |

> 效果都是**复利**（`1.15^lv`），不是线性加法。原因：线性加成在 D7 后会被通胀淹没，失去"跳变"感。

### 13.1 五个广告位（v0.8 保留结构）

### 13.2 频控（三层，不可放宽）

```
IF 今日总广告数 ≥ 30 THEN 全部静默
IF 单位今日数 ≥ 单位上限 THEN 该位静默
IF 距上次广告 < 30 秒 THEN 不弹
```

### 13.3 三个硬性视觉规则

| # | 规则 | 原因 |
|---|---|---|
| 1 | 「等恢复」与「看广告」按钮同尺寸同权重 | 不做逼氪式设计（PRD A6） |
| 2 | 显示「今天还能看 N 次」 | 透明，避免"被无限榨取"感 |
| 3 | 广告按钮点击后 0.3s 内不可响应；弹窗出现 0.5s 内半透明禁用 | 防误触 |

### 13.4 阶段迁移（v2.0 新增认知）

v1.1 模拟已证明：A1 对轻度玩家触发率为 0（因为金币足够买票）。v2.0 加日配额后 A1 恢复，但**后期票会变多**。所以广告结构必须随阶段迁移，不能指望单一位置：

| 阶段 | 主力位 | 日均广告 | 说明 |
|---|---|---|---|
| D1 | A1（补票）+ A2 | 4-6 | 票最紧 |
| D3 | A2 + A5（钻石） | 6-8 | 抽卡需求上来 |
| D7+ | A2 + A3（离线） | 6-10 | 单张奖金变大，A2 价值上升 |

> **北极星指标的实现路径不是"多加广告位"，而是"A2 的触发率"**。A2 在中奖后触发，而中奖率由票型决定 → 稳型（62% 中奖率）玩家的 A2 触发次数是冲型的 5 倍。这构成一个隐性引导：想多看广告的运营侧 vs 想少被打扰的玩家侧，靠票型自选平衡。

## 14. 经济系统与数值

### 14.1 三种货币（v0.8 保留）

| 货币 | 唯一来源 | 唯一出口 | 性质 |
|---|---|---|---|
| **金币** | 刮卡奖金（含倍率） | 设施升级 / 员工升级 / 买票配额 | 通胀型爽感货币 |
| **钻石** | 转盘 / 广告 A5 / 悬赏 / 图鉴 | 抽卡 | 稀缺型 |
| **票** | 自然恢复 / 员工柜台岗 / 悬赏 / 签到 / 广告 A1 / 金币买（配额） | 刮卡 | **真正的时间闸门** |
| 电 | 自然恢复 / 广告 A4 / 转转盘返还 | 转盘 | 副循环闸门 |

### 14.2 全局缩放基准

```
BASE  = 100                    // T1 面额，所有"绝对数值"的锚
SCALE = 当前已解锁最高票面额     // 用于转盘/悬赏等动态奖励
```

**所有固定奖励必须写成 `k × SCALE` 或 `k × BASE`，禁止写死具体数字。** 这是 v0.8 的另一个隐性缺陷：转盘写死 20 万，D1 时是天文数字，D7 时是零钱。

### 14.3 票供给（日）

| 来源 | 数量 | 说明 |
|---|---|---|
| 自然恢复 | `3600 / RECOVER_SEC` × 在线小时 | RECOVER_SEC = 45 ÷ (1 + 0.06×(迎宾Lv−1) + 迎宾岗加成) |
| 票池上限 | `60 + 15 × (迎宾Lv−1)` | Lv1 = 60，Lv30 = 495 |
| 员工柜台岗 | 8/25/80/300（每小时，按稀有度 ×1.08^lv） | 主力燃料后期 |
| 每日签到 | 20-100 | |
| 每日悬赏 | 30 | |
| 每周悬赏 | 1 张 T6 | |
| 广告 A1 | 20 × 8 = 160（上限） | |
| 金币买票 | 30 + 2×(迎宾Lv−1) | 配额 |
| 双星彩蛋（v0.8 保留） | 约 3.2%/张 → 赠 1 张同款 | 保留，作为"小惊喜" |

**首日真实供给** ≈ 90-140 张（在线 15 分钟）。**日消耗（15 分钟）** ≈ 36-50 张。

> 缺口 = 40-90 张 → 对应 2-4 次 A1 广告 + 悬赏。这就是商业模型的心脏，也是唯一需要精调的数（见 18.2）。

### 14.4 金币的通胀曲线（锚点表）

> 三个口径：**存量**（账号里有多少钱）、**单次会话产出**（一次 15-40 分钟能赚多少）、**收入/分钟**（瞬时速度）。

**校验方法**（可脚本化）：

```

```

### 18.2 测试期必须精调的三个数

| # | 参数 | 为什么最重要 | 调错的后果 |
|---|---|---|---|
| **1** | `FAC_BONUS`（1.15）+ `FAC_COST_RATIO`（1.16） | 决定升级节奏 = 决定"每 3 分钟一次跳变"是否成立 | 太低 → 升级太慢（用户抱怨的"推进慢"）；太高 → 数字爆炸失去意义 |
| **2** | `PEEK_CELLS`（2） | 决定"选择是否有用" = P1 支柱生死 | 1 格 → 玩家觉得三张一样（伪选择）；3 格 → RTP 提升 25%，经济过热 |
| **3** | `TICKET_RECOVER_BASE`（45s）+ `BUY_CAP_BASE`（30） | 决定票缺口 = 决定广告次数 = 决定收入 | 缺口太小 → 不看广告；太大 → 弃游 |

### 19.5 候选生成伪代码（核心新增逻辑）

```
function rollCandidates(ticketId, count):
    local list = {}
    local profiles = shuffle({"steady","normal","wild"})
    for i = 1, count do
        local profile = profiles[i] or randomProfile()
        local result = generateByProfile(ticketId, profile)   -- 走结果生成规范
        result.profile = profile
        result.peek = randomChoose(cells, PEEK_CELLS)         -- 随机挑 2 格
        -- 标记已揭开
        for _, idx in ipairs(result.peek) do result.revealed[idx] = true end
        list[i] = result
    end
    return list
end

-- 首张邀请票（仅新号第一张）：不随机
function rollFirstTicket():
    result = generateWithTier("T1", "steady", 5)   -- 固定二等奖

    return result
end
```

### 19.6 倍率计算（唯一入口，禁止散落）

```
function rewardMult():
    local m = 1
    m = m * math.pow(FAC_BONUS, state.fac.counter - 1)     -- 柜台
    m = m * (1 + backStaffBonus())                          -- 后场岗
    m = m * (1 + stampBonus())                              -- 图鉴
    m = m * (1 + titleBonus())                              -- 头衔
    m = m * (1 + 0.08 * state.facPrestige)                  -- 无限扩建
    return m
end

-- 所有奖金结算必须走： payout = tier.payout * rewardMult()
```
