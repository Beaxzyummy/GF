## 一、核心诊断：为什么 v0.8 不好玩

用户在真机上跑过 v0.8 后给出的原话是「太水了、完全看不懂玩法、推进节奏太慢」。这不是美术问题（界面已重做过一轮），是**机制层缺了三样东西**。以下每条都带数值证据，不是主观判断。

### 1.1 诊断一：每一张票都没有决策，只有操作

v0.8 的单张流程是「点票种 → 刮 → 看结果 → 再点一次」。三个动作，零个选择。玩家唯一能选的"票种"是严格按面额递增解锁的，**最优解唯一**（永远买得起的最贵那张），所以连"选票种"都是伪选择。

> 后果：玩家在 25 秒里做的是"体力劳动"，不是"玩游戏"。这就是"太水"的机制根源。MDA 框架下，v0.8 只有 **Mechanics**（刮除），**Dynamics** 是"更快地刮"，**Aesthetics** 只有"感官愉悦"一层，缺了 Challenge 和 Expression，所以爽完 3 分钟就空。

### 1.2 诊断二：没有任何"下一次"的承诺

v0.8 没有保底、没有进度条、没有目标、没有倒计时承诺。刮完一张，唯一的下一步是"再买一张"。玩家感受不到"我离某个东西越来越近"，只有"我的金币多了一点"。

> 后果：**期待管理为零 = 没有回访理由**。这正是用户说的"推进节奏太慢"的另一面：不是数字涨得慢，是**看不见终点**。

### 1.3 诊断三：数值失序，副循环打穿了主循环（最致命）

我按 v0.8 的真实数据表算了一遍期望值：

| 来源 | 单次期望产出 | 折算成「晨光」张数 | 说明 |
|---|---|---|---|
| 刮 1 张晨光（T1） | 6.80 币 | 1.0 | 主循环，25 秒 |
| 刮 1 张好运十倍 | **30.24 币**（RTP 3.02） | 4.4 | 面额仅 10 币，RTP 却是福彩的 2.2 倍 |
| 转 1 次转盘 | **6,050 币**（金币档加权） | **890 张** | 成本仅 1 电（5 分钟回 1 点） |
| 看 1 次「领奖加份」广告 | = 本次奖金 | — | 单张收益直接 ×2 |

> **副循环 : 主循环 ≈ 99 : 1。** 任何一个理性玩家的最优策略都是「等电、转盘、别刮票」。核心玩法在数值上被自己的附属系统废掉了——这是"水"的结构性原因，也是"转盘比刮卡爽"的真因。
>
> 同一份数据里还藏着第二个炸弹：**好运十倍 RTP 3.02，福彩 T1 只有 1.36**。用户说"最喜欢好运十倍"，一半是真喜欢这个玩法，另一半是**我们把它做成了数值上唯一划算的票**。v2.0 必须把这件事变成"设计出来的喜欢"，而不是"数值偏差下的唯一正解"。

### 1.4 诊断四："一次一大步"从未发生

v0.8 的面额梯是 5 / 20 / 80 / 300 / 1200 / 5000。首日玩家（15 分钟 ≈ 28 张）累计金币约 2.7 千，解锁"烫金"要刮满 40 张、解锁"丝绒"要 100 张——按首日节奏需要 2-4 天。**玩家在第一次看到"大数字"之前就走了。**

反例是转盘：一次就能给 20 万。所以玩家的"膨胀体验"全部来自副循环，进一步加固了 1.3 的问题。

### 1.5 诊断五：元游戏缺位，数字变大没有意义

v0.8 的员工只产金币，金币只能买票，而票受「免费票上限 20 张」锁死。结果：挂机 8 小时回来，能买的票还是 20 张，多出来的金币没有出口。"数字膨胀"没有承载物，变成了一个只会变长、不会改变任何东西的计数器。

### 1.6 诊断六：首个 60 秒是"大厅 + 说明弹窗"

v0.8 首屏是一个功能列表（6 个票种按钮 + HOT + 转盘 + 手机 + 玩法），新玩家的第一眼是**一堆他看不懂的名词**，且第一张票不保证中奖。用户说"完全看不懂玩法"，就是从这一屏开始的。

### 1.7 诊断汇总：一句话

> **刮刮乐的本质是被动随机，我们把它原样搬进了游戏，于是玩家的角色从"玩家"退化成"按钮"。v2.0 要在机制层面把决策权还给玩家，而不是再加特效。**

## 二、产品定义

### 2.1 一句话卖点（v2.1 修订）

> **一张 10 块钱的票，上面有 12 次机会。刮开一格，就少一次悬念。**

v2.0 的卖点是"刮开前你能先看到两格"（判断）。v2.1 在此基础上加了一条更硬的：**一张票不是一次抽奖，是十几次小判决**。这两条并不冲突——预揭让你在"买哪张"上有判断，多局让你在"刮哪格"上有节奏。

**v2.1 卖点三句话（商店页/视频脚本口径）**：

| 层级 | 文案 |
|---|---|
| 钩子（3 秒） | 这张票有 12 次机会，露出来的两格已经对上了。 |
| 差异（10 秒） | 5 块的票 8 次机会，50 块的票 40 次。刮刀钝了自己磨，刀越快刮得越快——但中不中跟刀没关系。 |
| 留存（30 秒） | 刮完不用急着看数，攒够一把去兑奖台一起兑，多攒几张多给一成。 |

### 2.2 产品定义（v2.1 修订）

《好运游戏厅》是一款纯单机、零充值、竖屏的**刮刮乐主题解压小游戏**。玩家经营一间小彩票柜台：票架上有 5 个价位、10 种票面，每张票有 8-40 次中奖机会；刮出来的票先进"待兑口袋"，攒够一把去兑奖台一次性兑。刮来的钱用来换更好的刀、升级柜台、解锁更贵的票面。

- 平台：TapTap 制造 ｜ 竖屏锁定 ｜ 100% 离线 ｜ 无内购 ｜ IAA 激励视频变现
- **单张时长：18-49 秒（按档位；加权平均 29.3 秒）** ｜ 单次会话：14-16 分钟 ｜ 内容纵深：D30
- 目标：3.6 周最小闭环（5 批），v2.1 在 v0.8 代码基线上做机制替换，不做推倒重写

### 2.3 三条不可让的体验底线（v2.1 新增）

| # | 底线 | 为什么不可让 |
|---|---|---|
| 1 | **刮完 0.5 秒内一定看得到本张中了多少** | 用户要"花钱才知道成绩"，但如果真的不给看，就是卸载。我们把诉求实现为"揭晓有仪式"，不是"信息收费"（GDD L.1） |
| 2 | **钝刀也能刮完，且不存在"跳过刮除"** | 一根是防付费墙（K.1 红线 2），一根是防玩法空心化（K.1 红线 3） |
| 3 | **票面数字是真票的，票名与图案必须是我们的** | 用户要真实感，但不能侵商标权（J.4 规避清单） |

## 三、目标用户与使用场景

### 3.1 主力画像（不变，但诉求重新定位）

| 维度 | 描述 |
|---|---|
| 年龄/性别 | 25-45 岁，女性约 55% |
| 场景 | 通勤 10-20 分钟、睡前 5-15 分钟、午休、排队 |
| 设备 | 中低端安卓，6.1-6.7 寸，骁龙 660 级 |
| 游戏经历 | 玩过《羊了个羊》《开心消消乐》，不玩重度 |
| 对"赌"的态度 | 抵触"赌"，但不抵触"刮"——他们刮的是手感和判断 |
| 核心诉求 | **「这一分钟我要刮到点东西，而且是我自己选的票」** |

> v1.0 把诉求写成"完全放空"，这是错的：完全放空 = 无聊。v2.0 的诉求是**低负荷的判断**；v2.1 再加一层：**这个判断要重复几十次**——像真的刮一张票，每一格都值得看一眼，但整体不费脑。

### 3.2 心理需求映射（自我决定论 → 具体设计）

| 需求 | v0.8 满足度 | v2.1 的承载 | 判定标准 |
|---|---|---|---|
| **自主** Autonomy | 无 | 挑档位（5/10/20/30/50）+ 单张 vs 整本 + 三选一 + 稳/平/冲 + 券给谁 + 换哪把刀 + 攒几张一起兑 | 每分钟 ≥2 个有效决策（埋点可验） |
| **胜任** Competence | 弱 | 预揭提供可学习的判断线索；**多局让"我会看格"这件事有练习空间**；换更好的刀立刻感到"我能刮得更快" | 老玩家 RTP 高于新玩家 ≥6%；刮刀更换后单张时长下降 ≥15% |
| **关联** Relatedness | 无 | 22 名员工的性格与班次、柜台从 1 张桌子到一条街、兑奖台上"店员陪你兑" | 图鉴收集率（D7 ≥50%） |

## 四、价值主张分层

| 层 | 时间尺度 | 玩家要的 | v2.1 给的 | 与 v1.0 的差别 |
|---|---|---|---|---|
| **即时层** | 0-30 秒 | 「我选对了」 | 预揭两局 → 判断 → 选中 → 刮开验证判断 | v1.0 只有"刮开那一下爽" |
| **循环层** | 3-15 分钟 | 「下一张一定更好」 | 手气槽每 10 张给 1 张运势券；口袋攒够 5/10/20 张整叠 +5/+8/+12%；每 3 分钟一次升级 | v1.0 只有"再买一张" |
| **成长层** | 1-7 天 | 「我的厅在变大」 | 柜台 30 级 + 2 设施 + 22 员工排班 + 刮刀 5 档 + 票面图鉴 40 章 | v1.0 只有员工挂机 |
| **身份层** | 7-30 天 | 「我是这条街的厅主」 | 头衔 6 阶 + 无限扩建 + 图鉴全满的终局仪式 | v1.0 只有资产总值数字 |

### 4.1 情绪承诺（设计契约，违反即 bug）

| 承诺 | 可测判据 |
|---|---|
| 我永远不会"倒退" | 全游戏不存在任何扣减已有资产的设计（除主动消费）；口袋的票永不过期 |
| 我每次都知道下一步是什么 | 任意界面都有且只有一个"下一步"引导 |
| 我的判断是有用的 | 预揭选择性增益 ≥6% RTP（可 A/B 验证） |
| 我不会被"差一点"耍 | 未中奖界面零提示、零暗示、零"再来一次"弹窗；命中格的 ×N 角标只出现在命中局 |
| **我刮完就知道中了多少**（v2.1） | 100% 的票在 100% 涂层后 0.5 秒内显示合计，且无任何付费/广告前置 |
| **我不会被"刮不动"卡住**（v2.1） | 刀刃再钝也能刮完；扫尾只处理最后 5%；无"次数用尽"字样 |

## 五、设计支柱（3 条，可判定）

| # | 支柱 | 判定问题（答"否"即违规） | 违反示例 |
|---|---|---|---|
| **P1** | **判断优先于运气** | 玩家在这 20 秒里做的选择，是否影响了他能拿到什么？ | 三选一但三张票概率完全相同且预揭无信息 → 违规 |
| **P2** | **进度只进不退** | 是否存在任何让玩家已获得的进度减少/清零的设计？ | 手气槽每天清零、连击断了扣奖励 → 违规 |
| **P3** | **每一步都看得见在长大** | 玩家每 3 分钟内是否至少有一次"跳变"（升级/解锁/大额入账/券到手）？ | 连续刮 10 分钟没有任何跳变 → 违规 |

> 三条支柱互斥性检查：P1 可能诱发"最优解唯一"（主导策略），故要求三档 RTP 完全相等（见 GDD 5.4）；P2 可能诱发"无限囤积"（运势券），故设上限 2 张；P3 可能诱发"数值通胀失控"（金币无出口），故设设施 30 级 + 无限扩建作为永久出口。

## 七、成瘾性设计原则（可执行条款）

> 立场：**我们的"再来一次"来自「下一次会比这次更好」，不来自「这次输了要赢回来」。**
> 以下 12 条为强制条款，评审逐条打勾；任一条不通过即不可提审。

### 7.2 反向使用"损失厌恶"

传统博彩用"怕失去"驱动（沉没成本、连输加压）。我们**反着用**：

| 传统做法 | 我们的做法 | 机制收益 |
|---|---|---|
| 损失厌恶 → 追损 | 进度厌恶 → 护住进度（手气槽永不清零，券可存 2 张，口袋永不过期） | 玩家怕"浪费券"、怕"口袋攒的白攒"，会为了用掉它而回来 |
| 稀缺倒计时 → 焦虑 | 确定性倒计时 → 安心（"再刮 2 张就有券"、"再 3 张整叠多给一成"） | 待办感替代焦虑感 |
| 近失（near-miss）→ 再来一次 | 预揭（真实信息）+ 多局（每格都是真判定） | 同样的多巴胺，没有欺骗 |
| 付费墙 → 卡进度 | 刀钝了慢 30%（仍可刮完）→ 自愿花币磨 | 同一件事，两种叙事：一个说"你不够快"，一个说"你的刀该磨了" |

### 8.4 判定线（上线后第 7 天复盘）

| 观测 | 结论 | 动作 |
|---|---|---|
| **局判定 <500/日** | 多局结构没被感知 | 检查票面是否把"共 N 次机会"露出来；必要时把默认档位从 5 元改 10 元（局数 8→12） |
| 决策数 <20/日 | 三选一没被理解 | 候选降到 2 张 / 加大预揭对比度 |
| `choice_regret` 差值 <6% | 预揭无信息价值 | `PEEK_CELLS` 2 → 3 |
| **单张时长中位数 <18 秒** | 刮感崩了（太快） | `SCRATCH_RATE_BASE` 3,300 → 2,700 |
| **单张时长中位数 >52 秒** | 太长，会被骂"累" | `SCRATCH_RATE_BASE` 3,300 → 3,900 |
| **卡壳率 >3%** | 扫尾没生效 | `SCRATCH_TAIL_AUTO` 0.05 → 0.08 |
| 广告 <4 次/日 | 票不够紧 | 下调票恢复速度 10% |
| 广告 >10 次/日 | 太紧，有疲劳 | 上调悬赏票量 |
| **A6 磨刀转化 >70%** | 金币磨刀太贵（免费路径失效） | `BLADE_SHARPEN_COST` 0.30 → 0.24 |
| **A7 兑奖转化 <45%** | 加成不诱人 | `AD_A7_BONUS` 0.50 → 0.60（上限 0.60） |
| **兑奖跳过率 >25%** | 仪式太长 | 普通揭晓 2.5 → 2.0 秒；整叠 4.0 → 3.2 秒 |
| **`book_purchase` 与 `choice_made` 收益差 >8%** | 整本或单张出现主导策略 | 调 `BOOK_DISCOUNT`（不要动 `PEEK_GAIN`） |
| D1 <35% | 首个 60 秒失败 | 重做 50-60 秒段（券 + 升级引导） |
