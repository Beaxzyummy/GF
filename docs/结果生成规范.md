# 结果生成规范（Result Generation Spec）

> **本文件修正 GDD 3.5 节的一个实现缺陷，是奖级判定的唯一权威说明。**
> 版本：v1.1 ｜ 修正日期：2026-11-05

---

## 一、发现的缺陷

GDD v1.0 的 3.5 节给出了各票的奖级分布表（如 T1：三等奖 24.00%、二等奖 8.00%、一等奖 2.60%、特等奖 0.40%），但 3.2 节的符号库写的是「9 格按权重随机抽符号」。

**这两者数学上不可能同时成立。**

### 验证

如果 9 格独立按权重抽符号，设「与中奖符号相同」的概率为 q：

- 中奖率 = 1 - (1-q)^9
- 要达到 T1 的 35% 中奖率，需要 q ≈ 0.047
- 此时「9 格全中」的概率 = 0.047^9 ≈ **1.1e-12**

即：**特等奖 0.40% 在随机填充模型下根本不可能出现，差了 9 个数量级。**

反推 q ≈ 0.60 时，特等奖能到 0.63%，但此时中奖率变成 100%，且三等奖占比只有 6.8%（GDD 写的是 24%）。

**结论：随机填充模型无法实现任何一张票的奖级分布。**

## 二、正确的实现模型：奖级先行，符号后填

### 2.1 生成流程

```
1. 读表：按 ticket_prizes.csv 的 probability 抽一次奖级（0/3/5/7/9）
2. 按奖级填充：
   - 若奖级为 N（N>0）：
     a. 从 9 格中随机选 N 格，填入「中奖符号」（从 3 个中奖符号里任选一个，保持一致）
     b. 剩余 9-N 格，从「非中奖符号」池中随机填（确保不会意外凑成更多匹配）
   - 若奖级为 0：
     9 格全部从「非中奖符号」池填，且保证匹配数 ≤ 2
3. 双星彩蛋：独立判定 3.2% 概率，若命中，在非中奖格里塞入 2 个 ★
```

### 2.2 关键约束

| 约束 | 说明 |
|---|---|
| **中奖符号必须唯一** | 3 个中奖符号中，只有 1 个是「有效匹配符号」，其余 2 个是干扰项 |
| **非中奖符号池必须排除有效符号** | 否则会出现「超出奖级」的意外匹配 |
| **奖级为 0 时限制匹配数 ≤ 2** | 若填出 3 个匹配，就变成了三等奖，与抽中的奖级矛盾 |
| **双星彩蛋的 ★ 不算匹配** | ★ 是独立标记，不参与奖级判定 |

### 2.3 伪代码

```
function generateTicket(ticketId):
    tier = weightedPick(prizeTable[ticketId])   // 0 | 3 | 5 | 7 | 9
    symbols = array(9)

    // 3 个中奖符号：第 1 个是有效符号，后 2 个是干扰
    winningSymbol = pick(MATCH_SYMBOLS)          // ✦ ✿ ◆ ● 之一
    decoys = pickTwo(exclude(winningSymbol))

    // 填充
    if tier > 0:
        positions = randomChoose(9, tier)
        for p in positions: symbols[p] = winningSymbol
        filler = NON_MATCH_POOL                    // 不含 winningSymbol
        for i in remaining: symbols[i] = pick(filler)
    else:
        // 保证匹配数 <= 2
        maxMatch = randomInt(0, 2)
        positions = randomChoose(9, maxMatch)
        for p in positions: symbols[p] = winningSymbol
        for i in remaining: symbols[i] = pick(NON_MATCH_POOL)

    // 双星彩蛋（独立）
    if random() < 0.032:
        emptySlots = indicesOf(symbols != winningSymbol)
        twoPositions = randomChoose(emptySlots, 2)
        for p in twoPositions: symbols[p] = STAR

    return { winningSymbol, decoys, symbols, tier }
```

## 三、对 GDD 的修正说明

| GDD 原文 | 修正后 |
|---|---|
| 3.2「符号库 5 种，按权重随机」 | 权重仅用于**视觉多样性**（填充非中奖格时），不决定奖级 |
| 3.5「奖级分布表」 | **保持有效**，这才是真实概率 |
| 「9 格中与中奖符号相同的个数 → 决定奖级」 | 反了。应为：**先定奖级，再按奖级填充符号** |

### 为什么这个修正不影响玩家感知

玩家看到的仍然是「9 格里刮出 N 个相同符号」，**完全符合真实刮刮乐的体验**。真实彩票也是这样：结果在印制时就已确定，刮开只是揭示。

这也正是我们遵守合规的地方——**公示的 24.00% 就是真实的 24.00%**。

## 四、对概率公示的影响

**无影响。** ticket_prizes.csv 里的 probability 就是最终的真实概率，公示页直接读这份表。

需要额外公示的一条：

> 「每张票的结果在生成时即已确定，刮开仅为揭示过程。」

这句话既解释了机制，也强化了「和真实彩票一样」的认知。

## 五、自检清单

```
□ 实现后跑 100 万次模拟，验证各奖级频率与 CSV 偏差 < 0.1%
□ 验证 T1 特等奖确实出现（约 4000 次）
□ 验证双星彩蛋触发率 = 3.2% ± 0.2%
□ 验证奖级为 0 时，匹配数从不为 3
□ 验证没有任何一格的符号超出「中奖符号 + 干扰 + 非中奖池 + ★」的范围
```
