## 1. 视觉身份

### 1.1 一句话定位

> **「一张能中奖的纸，被放进了一间打烊后仍亮着灯的彩票店。」**

不是赌场，是**印刷品**。不是霓虹堆砌，是**油墨与烫金**。
玩家第一眼应该觉得「这票是真的」，第二眼应该觉得「这店里还有好东西」。

### 1.2 三个关键词

| 关键词 | 含义 | 落到像素上 |
|---|---|---|
| **纸感（Paper）** | 票面是实物，有厚度、有纤维、有压痕 | 纸白底 + 1dp 内白边 + 底部 4dp 硬投影 + 极淡纤维噪点 |
| **金（Gold）** | 金是「值钱」的唯一隐喻，只给奖励与主行动 | 三停渐变 + 顶部 1dp 高光 + 底部 1dp 暗线，形成金属体积感 |
| **印刷（Print）** | 所有颜色来自油墨叠印，不是发光体 | 颜色饱和但发哑；边界锐利不发虚；不用大面积纯白纯黑 |

### 1.3 反面清单 —— 我们绝不做成什么样

| ❌ 绝不做 | 为什么 | 正确的做法 |
|---|---|---|
| 老虎机式的廉价霓虹堆砌（满屏紫粉流光） | 会被 TapTap 判为博彩向，且用户明确拒绝 | 霓虹只存在于 HOT 票这一小块，且用「深底 + 单色描边光晕」不用大面积渐变 |
| 纯黑背景 + 纯白文字 | 廉价、像未做设计的原型 | 底用 `ink-900 #120C09`（暖黑），字用 `text-100 #F5EFE3`（暖白） |
| 圆角一律 20dp 的「大软糖」 | 失去印刷品的硬朗 | 卡片 14 / 按钮 12-14 / 标签 11，**最大不超过 16**（弹窗除外） |
| 符号用 `✦ ✿ ◆ ● ★` 等装饰字符 | NotoSansSC 里没有，渲染成 □ | 只用汉字（福禄寿喜财）与 NanoVG 几何路径，见 §5 |
| 用 Emoji 当图标 | 平台字体不可控，样式跳脱 | 字标图标（汉字）+ 几何图标，见 §5.4 |
| 大面积纯色平涂无层次 | 平面化 = 草稿感 | 每个面至少「底色 + 1 层渐变 + 1 条高光/暗线」 |
| 中奖用爆炸式红光铺满全屏 | 赌博机观感 | 中奖用「金色光晕 + 彩纸 + 数字滚动」，画面仍保持克制 |
| 未中奖变灰、弹「很遗憾」 | GDD §11.5 明确禁止 | 保持原色，0.5s 后自动回选票页 |

## 2. 配色系统

> 所有色值同时给出 **hex** 与 **RGBA**（NanoVG 直接用 `nvgRGBA(r,g,b,a)`）。
> 命名规则：`层级-色相-明度`。Lua 侧统一挂在 `C` 表（见附录 A）。

### 2.1 品牌暗场（壳层 / 背景）

游戏厅是「打烊后仍亮着灯」的暖黑，不是纯黑。所有界面默认铺在这一层上。

| Token | Hex | RGBA | 用途 |
|---|---|---|---|
| `ink-900` | `#120C09` | `nvgRGBA(18,12,9,255)` | 全屏底色。**禁止用 #000000** |
| `ink-800` | `#1B120D` | `nvgRGBA(27,18,13,255)` | 底栏 / 顶栏 / 分区背板 |
| `ink-700` | `#241811` | `nvgRGBA(36,24,17,255)` | 卡片默认底色（当前原型已用，保留） |
| `ink-600` | `#2F2118` | `nvgRGBA(47,33,24,255)` | 卡片内凹区 / 进度条槽 / 输入位 |
| `line` | `#4A3626` | `nvgRGBA(74,54,38,255)` | 1dp 描边 / 分隔线 |
| `line-soft` | — | `nvgRGBA(255,255,255,20)` | 卡内浅分隔（比 line 更淡，用于卡片内部） |
| `vignette` | — | `nvgRGBA(0,0,0,120)` | 屏幕四角压暗（`nvgBoxGradient` 一圈） |

**壳层氛围光**（每个主界面顶部必须有，否则画面会「死」）：
```lua
-- 从屏幕顶部中央向下扩散的暖光，模拟店内射灯
local g = nvgRadialGradient(vg, W*0.5, -60, 40, H*0.55,
    nvgRGBA(212,175,55,26), nvgRGBA(212,175,55,0))
```

### 2.2 金 —— 品牌主强调

**金只给两件事：钱、主行动。** 其他地方出现金 = 违规。

| Token | Hex | RGBA | 用途 |
|---|---|---|---|
| `gold-100` | `#FFE9A8` | `nvgRGBA(255,233,168,255)` | 渐变高光停 / 光晕内芯 |
| `gold-300` | `#F6E29E` | `nvgRGBA(246,226,158,255)` | 主金文字（浅底上的「中奖」）/ 渐变上停 |
| `gold-500` | `#D4AF37` | `nvgRGBA(212,175,55,255)` | **品牌主金**。金额、金边框、图标 |
| `gold-700` | `#8A6A20` | `nvgRGBA(138,106,32,255)` | 渐变下停 / 金描边暗部 |
| `gold-900` | `#4A3610` | `nvgRGBA(74,54,16,255)` | 金底上的描边 / 阴影 |

**金渐变（烫金的标准配方，135° 自上而下）**：
```lua
local p = nvgLinearGradient(vg, x, y, x, y+h,
    nvgRGBA(246,226,158,255),   -- 顶：受光
    nvgRGBA(212,175,55,255))    -- 底：本色
```
再加一条下停到 `gold-700`：三停 `100% → 50% → 0%` 用时把 `nvgLinearGradient` 的两种颜色换成三停 `nvgLinearGradient` + 中间 `nvgStop` 不可用的情况下，用两次叠画（先画两停，再叠一层 `gold-700` alpha 0→90 的窄条在底部 30% 区域）。

### 2.8 用色纪律（三条）

1. **一屏之内，高饱和色块面积 ≤ 25%。** 其余交给暗场与纸白呼吸。
2. **金只出现在「奖励」与「主按钮」**，且同一屏最多 1 个金色主按钮。
3. **红绿并置只出现在体彩皮肤**，且必须伴随汉字或形状冗余（见 §9.3）。

## 3. 字体与字阶

### 3.1 字体现状与应对

只有 `NotoSansSC.ttf` 一套，**单字重（Regular）**。字体本身覆盖 GB2312 常用字，足够。

**没有粗体怎么办？** 三种合法手段（按优先级）：

| 手段 | 实现 | 适用 |
|---|---|---|
| **伪粗体** | 同文本画两遍，第二遍偏移 `(0.6, 0)` dp，同色 | 标题、票名、金额（≤ 24dp 效果好，>32dp 会糊） |
| **描边加粗** | 先 `nvgStrokeColor` + `nvgStrokeWidth(1.2)` 描同字形，再 fill | 大标题（招牌字），可配合描边色做金边 |
| **字号 + 色彩对比** | 靠 24dp vs 13dp 的落差建立层级 | 正文层级（最安全，默认用这个） |

> ⚠️ **禁用**：`nvgText` 的斜体/合成斜体、伪粗体偏移 > 1dp（会重影）。

### 3.2 字阶表（单位 dp，物理 = ×3）

| Token | 字号 | 行高 | 用途 | 字距 | 备注 |
|---|---|---|---|---|---|
| `D0` | 40 | 48 | 大奖金额（结算页） | 0 | 伪粗体 + 金渐变 |
| `D1` | 32 | 40 | 页面核心数字（转盘指针上方奖励） | 0 | |
| `H1` | 24 | 32 | 页面标题 / 票名 | +1 | |
| `H2` | 20 | 28 | 卡片标题 / 弹窗标题 | +0.5 | 伪粗体 |
| `H3` | 17 | 24 | 列表主文字 / 按钮文字 | 0 | |
| `B1` | 15 | 22 | 正文 | 0 | 行高 1.47 |
| `B2` | 13 | 20 | 次要正文 / 说明 | 0 | **中文正文下限** |
| `C1` | 12 | 16 | 标签 / 单位 / 角标 | +0.5 | |
| `C2` | 10 | 14 | 极小标签（**仅非信息性**：票号角标、装饰） | +1 | 禁止承载关键信息 |

### 3.3 特殊排版规则（中文注意点）

1. **金额数字**：`148,200` 千分位逗号；不做等宽处理（NotoSansSC 数字近似等宽，够用）；金额与单位之间**不留空格**（`500币` 不是 `500 币`），但单位字号降一档并降色。
2. **中文标点**：只用全角 `，。：「」`；**禁止**在汉字之间夹半角逗号；省略号用 `……`（6 点）不用 `...`。
3. **数字与汉字混排**：`Lv.3`、`×2`、`+5票` 一律半角，前后不加空格。
4. **标题不做两端对齐**，短标题居左；居中的只有弹窗标题与结算金额。
5. **行首禁则**：`，。：」` 不出现在行首。NanoVG 无自动避头尾，采用「手动断行表」：长文案在数据层就按 ≤14 字切句，避免运行期断行。
6. **最大行宽**：单行 ≤ 18 个汉字（360dp 屏），超过必须断行。
7. **大标题字距**：`H1` 及以上加 `+1~+2` dp 字距。中文加字距会显得「郑重」，这正是彩票该有的调性；正文**绝不能**加字距（会散架）。

### 3.4 文字颜色配对表（避免用错）

| 背景 | 主文字 | 次文字 | 禁用 |
|---|---|---|---|
| `ink-900/800/700` | `text-100` | `text-300` | `text-500` |
| 金渐变按钮 | `ink-paper #2B2118` | — | 白色（对比不足） |
| `paper-50` | `ink-paper` | `ink-paper-2` | `paper-300`（太淡） |
| `red-500` 色块 | `#FFF8EC` | `rgba(255,248,236,.78)` | 任何黄 |
| `#0B0918`（HOT） | `#FFFFFF` | `neon-cyan` | `gold-500`（发脏） |

## 4. 材质语言

> 本章是「不做成草稿」的核心。**每一个面都必须至少两层**：底色 + 一层质感 + 一条高光或暗线。
> 所有手法只用 NanoVG 已有的：`nvgLinearGradient` / `nvgRadialGradient` / `nvgBoxGradient` / 路径 / 半透明叠画。

### 4.1 烫金（Hot Foil）—— 用于金色按钮、金额、金框

四层叠加，顺序不可乱：

```
① 底色：nvgLinearGradient(垂直) gold-300 → gold-500 → gold-700
② 顶部内高光：矩形 (x+2, y+1, w-4, 1.5)  fill rgba(255,255,255,150)
③ 底部内暗线：矩形 (x+2, y+h-2, w-4, 1.5) fill rgba(74,54,16,120)
④ 斜向高光带（可选，仅大块金）：-20° 平行四边形，宽 w*0.18，
   fill nvgLinearGradient(横) rgba(255,255,255,0) → rgba(255,255,255,70) → rgba(255,255,255,0)
```

```lua
local function drawGold(nvg, x, y, w, h, r)
    local p = nvgLinearGradient(nvg, x, y, x, y + h,
        nvgRGBA(246,226,158,255), nvgRGBA(212,175,55,255))
    nvgBeginPath(nvg); nvgRoundedRect(nvg, x, y, w, h, r)
    nvgFillPaint(nvg, p); nvgFill(nvg)
    -- 下停暗部
    local p2 = nvgLinearGradient(nvg, x, y + h*0.55, x, y + h,
        nvgRGBA(138,106,32,0), nvgRGBA(138,106,32,150))
    nvgBeginPath(nvg); nvgRoundedRect(nvg, x, y, w, h, r)
    nvgFillPaint(nvg, p2); nvgFill(nvg)
    -- 顶部高光
    nvgBeginPath(nvg); nvgRoundedRect(nvg, x+2, y+1, w-4, 1.5, 0.75)
    nvgFillColor(nvg, nvgRGBA(255,255,255,150)); nvgFill(nvg)
end
```

### 4.2 镭射（Holographic）—— 仅用于「特等奖」「UR」这类稀缺时刻

三层不同角度的线性渐变叠加，每层 alpha 30-50，模拟薄膜干涉：

| 层 | 角度 | 颜色 |
|---|---|---|
| L1 | 0°（横） | `rgba(34,224,255,50)` → 透明 → `rgba(255,46,136,50)` |
| L2 | 60° | `rgba(180,255,60,45)` → 透明 → `rgba(139,92,246,45)` |
| L3 | 120° | `rgba(255,255,255,60)` 细条 × 4（每 12dp 一条，宽 2dp） |

> 只在**大奖结算**与**抽卡 UR** 两处使用，一屏面积 ≤ 30%。用多了就变成「廉价镭射纸」。

### 4.3 纸张纤维（Paper Grain）—— 每个票面必备

预生成一次（存表，不每帧随机，否则会闪）：

```lua
-- 初始化时生成，之后每帧按固定坐标重绘
local fibers = {}
for i = 1, 140 do
    fibers[i] = {
        x = math.random() * 340, y = math.random() * 520,
        len = 3 + math.random() * 9,
        a   = 5 + math.random() * 7,      -- alpha 5~12
        ang = math.random() * math.pi,
    }
end
```
- 纤维：1dp 长线，`rgba(201,185,155, a)`，随机角度
- 边缘压暗：`nvgBoxGradient(x, y, w, h, r, 10, rgba(0,0,0,0), rgba(0,0,0,22))` 画在纸面上
- **纸的厚度**：在票卡底部画 `0 3 0 rgba(0,0,0,88)` 的硬投影 + 顶边 1dp `rgba(255,255,255,160)` 内高光

### 4.4 金属拉丝（Brushed Metal）—— 涂层刮开前的银层

- 底：`nvgLinearGradient(135°)` `#DCE1E8 → #B9C0CB → #8A929F`
- 拉丝：每 2dp 画一条 1dp 横线，alpha 在 6/10 之间交替（用 `i % 2` 决定）
- 斜纹：每 8dp 一条 45° 线，`rgba(255,255,255,36)`，宽 3dp
- 中心高光：`nvgRadialGradient` 从格子中心，内径 0 alpha 60 → 外径 `cellH*0.8` alpha 0
- 「刮」字：`#6E7683`，字号 `cellH*0.32`，alpha 140，居中
- 边缘：1dp `rgba(0,0,0,46)` 内描边

### 4.5 霓虹（Neon）—— 仅 HOT 皮肤与「电量」图标

三遍叠画，从外到内：

```
① 外晕：同形状放大 6dp，fill rgba(color, 30)
② 中晕：同形状放大 2dp，fill rgba(color, 70)
③ 芯体：原形状，fill 提亮色（如 pink → #FF8FC0）
④ 描边：1.5dp 原色
```

> 只用 2 个颜色（pink + cyan），**绝不三色以上**。这是「不像赌博机」的关键。

### 4.6 光晕与压暗（全屏通用）

- **顶光**：`nvgRadialGradient` 从 `(W/2, -60)`，半径 `H*0.55`，`rgba(212,175,55,26) → 0`
- **四角压暗**：`nvgBoxGradient(0,0,W,H, 0, 80, rgba(0,0,0,0), rgba(0,0,0,110))`
- **中奖闪光**：全屏 `rgba(255,255,240, a)`，a 从 200 → 0，400ms

## 5. 图标与符号系统

### 5.1 铁律

> **只能使用 NotoSansSC 中真实存在的汉字与数字，以及 NanoVG 路径绘制的几何图形。**

### 5.2 可用汉字符号集（已逐个确认在 NotoSansSC 中）

**主符号（刮刮乐 9 格，5 种）**：

| 符号 | 色值 | 语义 | 几何辅助 |
|---|---|---|---|
| 福 | `#E85C4E` `nvgRGBA(232,92,78,255)` | 基础 | 无 |
| 禄 | `#E2BA48` `nvgRGBA(226,186,72,255)` | 基础 | 无 |

### 5.3 NanoVG 几何图形规范

所有几何图形统一在 **24×24 设计网格** 内，线宽 2dp，圆角端点（`nvgLineCap(vg, NVG_ROUND)`）。

|---|---|---|
| **铜钱** | `nvgCircle(cx,cy,9)` 描边 2.5 + 中心 7×7 方孔（`nvgRect`，fill 背景色挖洞） | 金币图标 |

| **速度斜线** | 平行四边形，-8° | HOT 皮肤 |

### 5.4 字标图标（本项目独创的图标方案）

既然没有图标字体、不能用 Emoji，**用汉字本身当图标**——这恰好非常符合中国彩票店的气质（招牌就是字）。

```
┌────────┐   40×40 dp 圆角方
│        │   bg: rgba(255,255,255,0.05)
│   厅   │   border: 1dp rgba(212,175,55,0.35)
│        │   字: 20dp, gold-500（选中）/ text-500（未选）
└────────┘   选中时：底部 3dp 金色短横 + 字形提亮
```

- 未选中：字色 `text-500`，无边框，无辉光
- 选中：字色 `gold-300`，边框 `rgba(212,175,55,120)`，底部 12×2dp 金色短横
- 按下：整体 `scale 0.94`，90ms

### 5.5 数字的视觉处理

金额是这款游戏的主角，数字必须被「设计」：

| 场景 | 处理 |
|---|---|
| 顶部 HUD 金币 | 13dp `gold-500`，前面加 18dp 铜钱图标 |
| 票面金额（200币） | 票面用 20dp `red-500` + 「币」12dp 灰色；**≥4 位（如 4,000 / 100,000）降为 16dp 并保留千分位**；列表卡的面额规则见 §6.2 |
| 中奖金额（结算） | 40dp `D0`，金渐变填充（用 `nvgLinearGradient` 做 `nvgFillPaint` 配 `nvgText` — 不支持时用纯 `gold-300` + 下方 2dp 金色短横） |
| 刮区奖金（50币） | 13dp `red-500`，「币」10dp |
| ×10 倍率 | 红底白字胶囊，11dp，旋转 -6° |

### 5.6 标点与半角字符的验证（防豆腐块第二道闸）

除了汉字与数字，界面上不可避免会出现少量非 CJK 字符。**上线前必须做一次字形验证**，否则会重演上一版的 □ 事故。

**必须验证的字符清单**（按风险从高到低）：

| 字符 | Unicode | 用途 | 风险 | 缺失时的替代 |
|---|---|---|---|---|
| `·` | U+00B7 | 间隔号（`体彩 · 顶呱刮`） | 中 | **用 NanoVG 画 1dp 实心圆点**代替，间距 6dp |
| `×` | U+00D7 | 倍数（`×2`、`×10`） | 中 | 画两笔 1.5dp 交叉斜线，或改用汉字「倍」（`10倍`） |

| `，。：」` | 全角标点 | 中文断句 | 极低 | — |

**验证方法**（一次性，10 秒）：

```

> **绝对禁止**：`✦ ✿ ◆ ● ★ ✚ ☘ ♪ ♥ →` 等装饰/箭头/符号字符，以及任何 Emoji（U+1F300 以上）。NotoSansSC 不保证覆盖，且即使覆盖，字形风格也与正文不统一。

│ │ 好运十倍        ┌──────┐  │  ← 左 6dp 色脊（皮肤主色，全高）

```

**面额数字的自适应规则（v2.0 数值放大后必须遵守）**

面额从两位数放大到五位数（`100` → `100,000`），右侧面额区宽度有限（固定 **104dp**，含打孔线间距）。规则如下：

| 面额位数 | 字号 | 示例 | 说明 |
|---|---|---|---|
| 1–3 位 | 17dp | `200币` | 默认 |
| 4 位（含千分位逗号） | 15dp | `4,000币` | 字号降一档，其余不变 |
| 5–6 位 | 15dp + 单位降为 9dp | `100,000币` | 数字必须横向压缩，**禁止换行** |
| 任何情况下 | — | — | 面额列**永不换行**（`white-space: nowrap` / NanoVG 单行绘制），超宽时先降字号，最低 13dp |

> 若五位数仍溢出（如同时显示「剩 N 张」），**优先压缩数字字号，而不是缩写**。

## 7. 动效原则

### 7.1 三条原则

1. **动作要「有重量」**：所有出现用 `easeOutBack` 轻微过冲（1.05-1.06），消失用 `easeIn` 直接走，不回弹。
2. **中奖要「有停顿」**：揭示前留 250ms 空白，让玩家意识到「发生了」。
3. **克制优先**：一屏内同时运动的元素 ≤ 3 组。粒子只在中奖/大奖时出现。

### 7.2 缓动曲线表（Lua 与 CSS 通用）

| 名称 | cubic-bezier | 用在哪 |
|---|---|---|
| `easeOutCubic` | `0.215, 0.61, 0.355, 1` | 通用出场、金额滚动 |
| `easeOutQuart` | `0.165, 0.84, 0.44, 1` | 转盘 |
| `easeOutBack` | `0.34, 1.56, 0.64, 1` | 弹窗、卡片入场 |
| `easeInOutQuad` | `0.455, 0.03, 0.515, 0.955` | 页面切换 |
| `easeInQuad` | `0.55, 0.085, 0.68, 0.53` | 消失 |

### 7.3 时长表

| 场景 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 按钮按下 | 90ms | easeOut | `scale 0.96` + 下移 1dp |
| 按钮抬起 | 160ms | easeOutBack | 回弹到 1.0 |
| 页面切换 | 250ms | easeInOutQuad | 新页从右滑入 24dp + 淡入 |
| 卡片入场（列表） | 280ms | easeOutBack | 依次错开 40ms，最多错开 4 张 |
| 弹窗出现 | 200ms | easeOutBack | scale 0.92 → 1.0 |
| 弹窗关闭 | 150ms | easeInQuad | scale 1.0 → 0.96 + 淡出 |
| **刮除单格** | 120ms | easeOutCubic | 涂层 `scale 1 → 0.92` 同时 alpha 1 → 0，格内容从 0.94 弹到 1.0 |
| 刮除进度条 | 200ms | easeOut | 无回弹 |
| 自动全揭 | 350ms | easeOutCubic | 每格错开 40ms |
| **开奖前停顿** | **250ms** | — | 什么都不发生，只有极轻的屏息感 |
| 光晕爆发 | 500ms | easeOutCubic | 径向光晕半径 0 → 260dp，alpha 180 → 0 |
| 金额滚动 | 900ms | easeOutCubic | 每帧 `cur += (target-cur) * 0.15`，末尾吸附 |
| 彩纸 | 1200ms | 物理 | 初速 -320~-520 dp/s 向上，重力 900 dp/s²，旋转 ±360°/s |
| 屏幕闪光 | 400ms | easeOut | 全屏白 alpha 200 → 0 |
| **转盘** | **3200ms** | easeOutQuart | 4 圈 + 落位角；最后 400ms 加 ±1.5° 阻尼抖动 |
| 转盘落位高亮 | 400ms | easeOutBack | 中奖扇区亮度提升 + 白色描边 |
| 批量结算（10 张） | 1200ms | easeOut | 每张错开 90ms |
| Toast 进/出 | 200ms | easeOut / easeIn | 上滑 12dp |
| 广告按钮金边呼吸 | 1200ms × 2 | easeInOutQuad | 循环，周期 2.4s |

### 9.2 特性矩阵

| 特性 | 状态 | 实现规格 |
|---|---|---|
| 对比度（正文） | ✅ 必须 | 正文 ≥ **4.5:1**，大字（≥24dp）≥ **3:1** |
| 对比度（非文本） | ✅ 必须 | 按钮边框、图标、进度条 ≥ **3:1** |
| 字号下限 | ✅ 必须 | 中文正文 **≥13dp**（物理 39px）；关键信息 ≥15dp；10dp 仅限票号等装饰 |
| 触控目标 | ✅ 必须 | **≥44×44dp**，间距 ≥8dp |
| 色盲冗余 | ✅ 必须 | 见 §9.3 |
| 动效减弱 | ✅ 必须 | 设置内置「减少动效」开关：转盘 400ms 转 1 圈直接出结果；彩纸数量 24→6；屏幕闪光取消；页面切换改为直接切 |
| 文字缩放 | ⚠️ 部分 | 提供「大字模式」：全局字阶 ×1.15（`D0` 除外），卡片高度自适应 |
| 声音替代表达 | ✅ 必须 | 所有音效反馈必须有视觉等价物（中奖有金色光晕与金额跳动，不依赖音效） |

| 屏幕阅读 | ❌ 不做 | 平台无稳定读屏支持 |

### 9.3 色盲友好（含实测对比度）

**关键测量**（WCAG 相对亮度）：
- `red-500 #C8102E` 亮度 L ≈ **0.128**
- `green-500 #00A15C` 亮度 L ≈ **0.262**
- `green-700 #00713F` 亮度 L ≈ **0.122**

**结论与强制规则**：

1. **`red-500` 与 `green-700` 亮度几乎相同（0.128 vs 0.122）**，红绿色盲下完全无法区分。
   → **规则：红与绿永不单独承载「成功/失败」「中/未中」的语义。** 两者并置时只做装饰（体彩票头的红条 + 绿线），语义必须由**汉字**承担（「中」字圆章、「未」字）。
2. `green-500` 在 `paper-50` 上对比度仅 **3.1:1**，**禁止**用作正文文字色；纸面上的绿色文字一律用 `green-700`（5.7:1）。
3. `red-500` 在 `paper-50` 上 **5.5:1**，可作正文。
4. `gold-500` 在 `ink-900` 上 **9.1:1**，安全。
5. `text-500 #8A7C68` 在 `ink-700` 上仅 **3.9:1** → 不达正文标准，**只允许 ≥14dp 且非关键**。
6. 中奖状态除了颜色，必须同时有：**加粗描边（2dp 红框）** + **「中」字圆章** + **底色变浅（#FFF6D8）** 三重冗余。

### 9.4 深色模式的说明

本项目**只有一套配色**（暖黑暗场），不提供浅色模式。
理由：票面本身是「亮面」，若再提供浅色壳层，票面就会失去「实物纸」的对比，反而更难读。

### 9.5 自检清单（每次改 UI 后跑一遍）

- [ ] 所有文字色在对应底色上对比度 ≥ 4.5:1（或字号 ≥24dp 时 ≥3:1）
- [ ] 没有 12dp 以下的正文
- [ ] 所有可点元素 ≥44×44
- [ ] 中奖/未中奖状态在灰度截图下仍可区分
- [ ] 没有任何 `✦ ✿ ◆ ● ★` 等非 CJK 字符
- [ ] 没有使用 `#000000` / `#FFFFFF` 纯色
- [ ] 每个面至少有「底色 + 一层质感」
- [ ] 一屏内只有 1 个金色主按钮

# 10. 真实票面解剖学（八层）

> 本章解决一件事：**让一张票看起来是从印刷厂出来的，而不是从设计软件里导出的。**
> 参照物：`piaoshu.md` 中 298 款真实票的面额、命名、配色与版式共性；以及参考录屏里那张 12–16 格的柜台票。
> 每层都给出 **NanoVG 可计算的参数**（dp 坐标、角度、线宽、alpha、色值）。写不出参数的描述一律不进本章。

## 10.0 坐标基准与票面画布

| 常量 | 值 | 说明 |
|---|---|---|
| 票面宽 `TW` | **328** | 360 屏宽 − 左右各 16 |
| 票面高 `TH` | **自适应**，见 §13.5 高度核算表 | 一张票 = 一屏，不滚动 |
| 外框内缩 `FR` | **0** | 外框线压在票面边界上（`nvgRect` 描边会外溢 0.6，需先 `nvgSave` + clip） |
| 双框间距 | **5** | 外线在 0，内线在 5 |
| 纹样带高 `BH` | **9** | 位于 inset 5 → 14 之间，只做上、下两条（左右只留双线，这是真票的通行做法） |
| 纸边留白 `PM` | **12** | 纹样带内侧到内容区的距离 |
| 内容区宽 `CW` | **296** | `328 − 2×16`（16 = 5 框距 + 9 纹样带 + 2 呼吸，取整为 16） |
| 圆角 `TR` | **3** | 印刷票面几乎直角，只做 3dp 破刃，**禁止** ≥8 |

```lua
-- 票面画布：所有层共用的基准
local TW, TR = 328, 3
local function ticketFrame(vg, x, y, w, h)
  nvgSave(vg)
  nvgBeginPath(vg); nvgRoundedRect(vg, x, y, w, h, TR); nvgClip(vg)  -- 后续所有绘制被裁进票面
end
local function ticketFrameEnd(vg) nvgRestore(vg) end
```

## 10.1 第 1 层 · 纸张底

真票的纸**不是纯色**：它是米黄纸基 + 四色印刷网点 + 纸纤维 + 边缘脏。四件事叠加，缺一件就"假"。

| 子层 | 手法 | 参数 |
|---|---|---|
| ① 纸基 | `nvgRect` 纯色填充，色取皮肤 `paper` token（§11） | 例：`#F7EFDF` / `nvgRGBA(247,239,223,255)` |
| ② 网点（halftone） | 两组斜线交叉，模拟 175 线印刷网点的观感 | 45° / −45° 各一组，线宽 **0.8dp**，间距 **3.5dp**，alpha **7 / 5**，色 `rgba(107,91,71,α)` |
| ③ 纸纤维 | 预生成 120 条短线，**固定 seed，不每帧随机** | 长 3–9dp，线宽 0.7dp，角度 `rand*π`，alpha 6–12，色 `paper-300 #C9B99B` |
| ④ 边缘压暗 + 脏角 | `nvgBoxGradient` 内阴影 + 四角半透明弧 | 内阴影 `feather 9`，`rgba(107,91,71,0) → rgba(107,91,71,30)`；四角各 2 段 `r=4` 弧，`rgba(107,91,71,18)` |

```lua
-- 网点：绘制量控制是重点。全票面满铺约 2 万次圆点 → 必卡。
-- 用"斜线"代替"圆点"，绘制量降到约 220 条线段，肉眼观感等价。
local function halftone(vg, x, y, w, h, rgb)
  local a = nvgRGBA(rgb[1], rgb[2], rgb[3], 7)
  local b = nvgRGBA(rgb[1], rgb[2], rgb[3], 5)
  nvgStrokeWidth(vg, 0.8)
  local step = 3.5
  -- 45°
  nvgStrokeColor(vg, a); nvgBeginPath(vg)
  for i = 0, math.floor((w + h) / step) do
    local d = i * step
    nvgMoveTo(vg, x + d, y); nvgLineTo(vg, x + d - h, y + h)
  end
  nvgStroke(vg)
  -- -45°
  nvgStrokeColor(vg, b); nvgBeginPath(vg)
  for i = 0, math.floor((w + h) / step) do
    local d = i * step
    nvgMoveTo(vg, x + d - h, y); nvgLineTo(vg, x + d, y + h)
  end
  nvgStroke(vg)
end
```

> **性能红线**：网点只在**内容区**（`CW × 内容高`）铺，纹样带与票根不铺。整票网点线段上限 **260 条**。

## 10.2 第 2 层 · 装饰边框（回纹 / 藤蔓 / 角花）

这是「一眼真票」的最大贡献者，也是最花代码的一层。三种母题各给一套可复用画法。

### A. 双线框（所有皮肤必备）

```
外线：inset 0，线宽 1.2dp，皮肤 border 色，alpha 255
内线：inset 5，线宽 0.6dp，同上色，alpha 150
两线之间：填充皮肤 paper 色 alpha 0（留白），不做任何填充
```

### B. 回纹带（墨绿国潮 / 中国红 用）

回纹 = 单胞重复。**单胞 8×8dp，线宽 1.0dp，路径固定**：

```
M 0,7  L 0,1  L 6,1  L 6,5  L 2,5  L 2,3.2  L 4,3.2
```
（起点在左下，逆时针内收，收口朝下——这是回纹"不断头"的关键：单胞之间靠 8dp 节距无缝相接。）

```lua
-- 沿水平边铺回纹带。y0 = 带顶；dir = 1 正向（上边）/ -1 翻转（下边）
local function keyFret(vg, x0, y0, len, dir)
  local u = 8
  local n = math.floor(len / u)
  local P = {{0,7},{0,1},{6,1},{6,5},{2,5},{2,3.2},{4,3.2}}
  nvgStrokeWidth(vg, 1.0); nvgBeginPath(vg)
  for i = 0, n - 1 do
    local ox = x0 + i * u
    for k = 1, #P do
      local px, py = ox + P[k][1], y0 + (dir > 0 and P[k][2] or (8 - P[k][2]))
      if k == 1 then nvgMoveTo(vg, px, py) else nvgLineTo(vg, px, py) end
    end
  end
  nvgStroke(vg)
end
```

### C. 藤蔓带（生肖 / 节庆 / 锦鲤 用）

- 主蔓：`y = 4.5 + 2.0 * sin(x / 14 * 2π)`，每 14dp 用一段 `nvgBezierTo` 近似，控制点取切线 ±4dp，线宽 1.2dp
- 叶片：每 7dp 一片，交替上下，`nvgEllipse(cx, cy, 3.2, 1.6)` 按切线角 `nvgRotate`，**实心填充**
- 花点：每 28dp 一个 `nvgCircle(r=1.6)`，实心

### D. 角花（四角，16×16，镜像复用一次写四次变换）

```lua
-- 卷草角花：3 段曲线，画在 16×16 的左上角坐标系里
local function cornerOrn(vg, x, y, s, mirrorX, mirrorY)
  nvgSave(vg)
  nvgTranslate(vg, x, y)
  nvgScale(vg, mirrorX and -1 or 1, mirrorY and -1 or 1)
  nvgTranslate(vg, mirrorX and -16 or 0, mirrorY and -16 or 0)
  nvgStrokeWidth(vg, 1.2); nvgBeginPath(vg)
  nvgMoveTo(vg, 0, 14);  nvgBezierTo(vg, 0, 6,   6, 0,   14, 0)
  nvgStroke(vg)
  nvgStrokeWidth(vg, 0.7); nvgBeginPath(vg)
  nvgMoveTo(vg, 2.6, 14); nvgBezierTo(vg, 2.6, 8, 8, 2.6, 14, 2.6)
  nvgStroke(vg)
  nvgBeginPath(vg); nvgArc(vg, 5.2, 5.2, 2.6, 0, 1.55 * math.pi, 1)  -- 内卷
  nvgStroke(vg)
  nvgBeginPath(vg); nvgCircle(vg, 5.2, 5.2, 0.9); nvgFill(vg)          -- 芯点
  nvgRestore(vg)
end
-- 调用：左上(0,1,false,false) 右上(1,1,true,false) 左下(0,0,false,true) 右下(1,1,true,true)
```

> **绘制预算**：双线框 2 + 上下回纹带 2（各 1 次 stroke，内含 n 段）+ 角花 4×4 = **20 次 draw 调用**。可接受，且**必须缓存**（见 §10.9）。

## 10.3 第 3 层 · 票名标题区（压印）

**这里有一个必须承认的硬约束：项目只有 `NotoSansSC`（黑体），没有宋体，也没有第二字重。**

用户要的「黑色粗宋体/楷体压印」在现有字体下无法真正实现。给出两个方案，**默认走 A**：

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **A · 黑体近似宋**（默认） | 横向压缩 `scaleX 0.94` + 0.7dp 描边 + 字距 −0.5 + 压印三层 | 0 | 可上，但要知道「像粗黑，不像宋」 |
| B · 追加 NotoSerifSC 子集 | 只保留 800 个用到的字，约 **250–320 KB** | 包体 +0.3MB、多一套字体加载 | **建议做**，这条不改，票名永远差一口气 |

**压印（letterpress / deboss）配方 —— 三层，顺序不可乱**：

```
① 亮唇（右下）：同文本，偏移 (+0.5, +0.7)，色 rgba(255,255,255,110)
② 墨身：       同文本，原位，色 = 皮肤 title 色（默认 #171310）
③ 暗唇（左上）：同文本，偏移 (−0.4, −0.5)，色 rgba(0,0,0,38)
```

```lua
local function pressedText(vg, x, y, s, size, col, ls)
  nvgFontSize(vg, size); nvgTextLetterSpacing(vg, ls or 0)
  nvgTextAlign(vg, NVG_ALIGN_CENTER + NVG_ALIGN_MIDDLE)
  nvgFillColor(vg, nvgRGBA(255,255,255,110)); nvgText(vg, x+0.5, y+0.7, s, nil)  -- ①
  nvgFillColor(vg, nvgRGBA(0,0,0,38));        nvgText(vg, x-0.4, y-0.5, s, nil)  -- ③
  nvgFillColor(vg, col);                      nvgText(vg, x, y, s, nil)          -- ②
  nvgText(vg, x+0.65, y, s, nil)                                                  -- 伪粗体
end
```

| 参数 | 值 |
|---|---|
| 标题区高 | **32**（16 格版）/ 34（9 格版） |
| 字号 | **26**（2 字票名）/ 22（3–4 字） |
| 字距 | **−0.5**（负值才「紧」，正字距会散成海报） |
| 垂直位置 | 区中心，`NVG_ALIGN_MIDDLE` |
| 伪粗体偏移 | **0.65dp**（v2.0 的 0.6 略细，26dp 下需要 0.65） |
| 标题下分隔线 | 距文字底 6dp，宽 = 标题宽 + 24，高 **0.8dp**，皮肤 border 色 alpha 60 |
| kicker（小标） | 8.5dp，字距 **3**，色 title 色 alpha 140，位于标题上方 9dp 或与标题同行右侧 |

> **禁止**：标题用渐变填充 + 外发光（那是游戏 UI）。烫金感靠 §4.1 的三层烫金配方，且只在 `烫金`、`鎏夜` 两款皮肤上使用。

## 10.4 第 4 层 · 玩法说明区

真票的规则文字是**缩印的**，且一定有「小标题 + 正文」两段节奏。

| 参数 | 值 |
|---|---|
| 区高 | **24**（两行）/ 28（含小标题） |
| 字号 | 正文 **10.5dp**，行高 **13.5**；小标题 9dp，字距 2 |
| 左右内缩 | 12 |
| 行首符号 | `nvgCircle(r=1.2)` 实心，皮肤主色，距左 12，与首行中线对齐 |
| 行长 | ≤ **15 汉字**，超出必须手动断行（NanoVG 无避头尾） |
| 色 | `ink-paper-2 #6B5B47`，或皮肤主色 alpha 190 |
| 分隔 | 区上方 1 条 `0.6dp` 虚线，`rgba(107,91,71,40)`，5 on / 4 off |

> ⚠️ **可访问性妥协（必须记录）**：10.5dp 低于 §9.2 规定的中文正文下限 13dp。
> 这是「票面要像真票」与「文字要能读」的正面冲突。裁决规则：
> ① 票面玩法说明允许 10.5dp，但**同一屏必须存在等价的大字入口**（顶栏「规则」→ 弹窗，正文 15dp）；
> ② 开启「大字模式」时，票面文字统一升到 **12.5dp**，格高 ×1.12，票面允许纵向溢出 8dp 由 flex 吸收；
> ③ 6.5–8.5dp 的微缩文字（票号、缩微印刷）**只做装饰，不承载任何信息**（符合 §3.2 的 C2 规则）。

## 10.6 第 6 层 · 我的号码区（12–20 格栅格）

## 10.8 第 8 层 · 票根

票根是「防伪」的视觉证据。四件套，缺一件就不像真票。

| 元素 | 位置 | 参数 |
|---|---|---|
| **撕线** | 票根顶边 | 虚线上 1dp，5 on / 4 off，`rgba(107,91,71,55)`；两端各 1 个 `r=3` 半圆缺口（用纸底色盖出） |
| **条形码** | 左起 0 | 高 **14**，条宽取 {1, 1.5, 2, 2.5, 3}dp，间隙取 {1, 1.5}dp，总宽 **96**，固定 seed 生成 38–44 根；色 `rgba(23,19,16,215)` |
| **票号** | 条形码右侧 | 8dp，字距 1.2，`rgba(23,19,16,190)`，格式 `NO.20261106 0417 8832` |
| **微缩文字** | 票根底行 | 5dp，alpha 90，重复串 `GUOYUN YOUXITING · NOPRIZE · ZGFC`，**纯装饰** |
| **保安区** | 右下 | **34 × 18** 银块（用 §12 的刮层配方）+ 「刮开无效」5.5dp 双行，本层不刮 |
| **点阵码** | 票号旁 | 7×7 圆点，`r=0.8`，间距 2.4，固定 seed 半数填充 |
| 票根高 | — | **34**（含 8dp 下留白） |

```lua
-- 条形码：固定 seed，保证同一票号每次渲染一致（否则会闪）
local function barcode(vg, x, y, w, h, seed)
  math.randomseed(seed)
  local cx = x
  nvgFillColor(vg, nvgRGBA(23,19,16,215))
  while cx < x + w do
    local bw = ({1,1.5,2,2.5,3})[math.random(5)]
    nvgBeginPath(vg); nvgRect(vg, cx, y, bw, h); nvgFill(vg)
    cx = cx + bw + ({1,1.5})[math.random(2)]
  end
  math.randomseed(os.time())  -- 复原，避免污染其他随机
end
```

## 10.9 绘制顺序与缓存策略（技术美术要点）

**八层必须按此顺序叠**（后画的压住先画的）：

```
1 纸张底 → 2 边框 → 3 票名 → 4 玩法说明 → 5 对照号 → 6 号码格内容
        → 7 刮层（最上） → 8 票根（画在刮层之后，因为保安区在票根上）
```

**绘制预算（16 格版实测路径数）**：

| 层 | 路径/调用数 | 备注 |
|---|---|---|
| 纸 | 4 | 含 260 条网点线段 |
| 框 | 20 | 4 角花 × 4 + 双线 + 2 带 |
| 标题 | 4 | 压印 3 + 伪粗体 1 |
| 说明 | 6 | 2 行 + 2 点 + 1 虚线 |
| 对照号 | 9 | 3 框 × 3 |
| 号码格 | ~112 | 16 格 × 7（框+底+号+奖+…） |
| 刮层 | ~90 | 未刮格 × (底+拉丝 8+斜光+水印) |
| 票根 | ~50 | 条形码 40 + 号 + 框 |
| **合计** | **≈295** | 60fps 下勉强，**必须做缓存** |

**缓存三级策略（按引擎能力择一）**：

| 级别 | 做法 | 收益 |
|---|---|---|
| **L1（必须）** | 网点、纤维、角花、条形码的**随机量在初始化时生成成常量表** | 避免每帧 `math.random` 造成的闪烁与抖动 |
| **L2（建议）** | 把「纸 + 框 + 标题 + 说明 + 对照号 + 票根」合成一张离屏图（若框架支持 `nvgCreateImageFromHandle` / FBO），只在换票时重绘 | 每帧路径降到 ~200 |
| **L3（可选）** | 已刮开的格子内容也进入离屏图，只留未刮格每帧重绘 | 每帧路径降到 ~40 |

> 若引擎不支持离屏，则至少保证：**票面每帧只在「刮层覆盖率变化」时重绘**，进度条/按钮单独一层。

# 12. 刮层与刮痕规范

> 这是整个项目最难的一层。参考录屏里那张票的银色涂层有**横向拉丝反光**，且刮开边缘是**不规则的手刮毛边**——这两点决定了"真不真"。

## 12.1 涂层四配方

| 配方 | 用于 | 渐变三停（108°） | 拉丝 alpha | 斜光 alpha |
|---|---|---|---|---|
| **A 亮银** | S1 S2 S3 S7 | `#D9DEE5 → #C0C7D1 → #98A0AC` | 11 / 5 | 52 |
| **B 哑银** | S4 S5 | `#D2D6DA → #B9BEC4 → #979CA3` | 8 / 4 | 38 |
| **C 冷银** | S6 | `#E3EBF1 → #C6D2DC → #9FAEBC` | 12 / 6 | 46 |
| **D 暗金** | S8 | `#9A8A62 → #6E6349 → #4B4436` | 14 / 7 | 34 |

**四层叠加（顺序固定）**：

```
① 底渐变：nvgLinearGradient(x,y → x+w*0.21, y+h)   -- 约 108°
② 拉丝：每 2dp 一条 1dp 横线，alpha 交替
③ 斜光带：−24° 平行四边形，宽 = w*0.42，white 0→52→0
④ 网纹：3dp 间距 0.8dp 圆点，alpha 6
⑤ 边：顶 1dp rgba(255,255,255,150)；右+下 1dp rgba(58,64,72,70)
```

```lua
local FOIL = {
  A = {{217,222,229},{192,199,209},{152,160,172}},
  B = {{210,214,218},{185,190,196},{151,156,163}},
  C = {{227,235,241},{198,210,220},{159,174,188}},
  D = {{154,138,98},{110,99,73},{75,68,54}},
}

local function drawFoil(vg, x, y, w, h, preset)
  local c = FOIL[preset]
  -- ① 底
  local p = nvgLinearGradient(vg, x, y, x + w*0.21, y + h,
      nvgRGBA(c[1][1],c[1][2],c[1][3],255),
      nvgRGBA(c[3][1],c[3][2],c[3][3],255))
  nvgBeginPath(vg); nvgRoundedRect(vg, x, y, w, h, 2)
  nvgFillPaint(vg, p); nvgFill(vg)
  -- ② 拉丝
  nvgStrokeWidth(vg, 1.0)
  for i = 0, math.floor(h/2) do
    local yy = y + i*2
    local a = (i % 2 == 0) and 11 or 5
    nvgStrokeColor(vg, nvgRGBA(255,255,255,a))
    nvgBeginPath(vg); nvgMoveTo(vg, x, yy); nvgLineTo(vg, x+w, yy); nvgStroke(vg)
  end
  -- ③ 斜光带（−24°）
  local bw = w * 0.42
  local ang = math.rad(-24)
  local cx, cy = x + w*0.5, y + h*0.5
  nvgSave(vg); nvgTranslate(vg, cx, cy); nvgRotate(vg, ang)
  local gp = nvgLinearGradient(vg, -bw/2, 0, bw/2, 0,
      nvgRGBA(255,255,255,0), nvgRGBA(255,255,255,52), nvgRGBA(255,255,255,0))
  nvgBeginPath(vg); nvgRect(vg, -bw/2, -h*0.9, bw, h*1.8)
  nvgFillPaint(vg, gp); nvgFill(vg); nvgRestore(vg)
  -- ④ 网纹
  nvgFillColor(vg, nvgRGBA(58,64,72,6))
  for i = 0, math.floor(w/3) do
    for j = 0, math.floor(h/3) do
      nvgBeginPath(vg); nvgCircle(vg, x + i*3, y + j*3, 0.4); nvgFill(vg)
    end
  end
  -- ⑤ 边
  nvgBeginPath(vg); nvgMoveTo(vg, x, y+0.5); nvgLineTo(vg, x+w, y+0.5)
  nvgStrokeColor(vg, nvgRGBA(255,255,255,150)); nvgStrokeWidth(vg,1); nvgStroke(vg)
end
```

> ④ 网纹在 69×42 的格上是 `24×15 = 360` 个圆 —— **太重**。
> 优化：网点只画在 `i % 2 == 0 and j % 2 == 0` 的隔点上（90 个），或干脆**省掉 ④**（拉丝 + 斜光已足够）。**默认省掉**，仅在 `cellW ≥ 140`（L10）时开启。

## 12.2 刮除 mask 与手刮毛边（核心）

### 为什么不能用"格子二值开合"

真票的刮除是**连续厚度衰减**：刮过的银层先变薄（半透明雾面），再露出纸，边界是**锯齿状的、带粉末残留的**。
NanoVG 没有逐像素遮罩、没有笔刷贴图（零位图），所以只能在"格子级二值"与"子格级像素化"之间折中。

**方案：每格维护 8×5 = 40 个子格的覆盖位图。**

```
子格尺寸：sw = cellW / 8, sh = cellH / 5
刮刀：圆 (px, py)，半径 R（见 §12.3 分档）
命中判定：子格中心 (cx, cy) 满足 |dx| + |dy| × 0.85 < R × 1.05  → 置 1
          （曼哈顿距离，天然给出菱形边界，比圆形更像"手推"）
渲染：对每个 cover == 0 的子格画一个圆角矩形 r = 1.2，
      并按 hash(cellId, i, j) 向外扩 0~1.4dp —— 这 1.4dp 就是"毛边"的来源
整格揭底：Σcover / 40 ≥ 0.60 → 该格转 opened（120ms easeOutCubic 揭示）
```

```lua
-- 子格外扩量：预生成，绝不每帧随机
local function jag(ci, i, j)
  local h = (ci * 73856093) ~ (i * 19349663) ~ (j * 83492791)
  return (h % 15) / 10  -- 0.0 ~ 1.4
end

-- 画一格未刮完的涂层
local function drawPartialFoil(vg, x, y, cw, ch, cover, ci, preset)
  local sw, sh = cw/8, ch/5
  for i = 0, 7 do
    for j = 0, 4 do
      if cover[i*5 + j] == 0 then
        local e = jag(ci, i, j)
        drawFoil(vg, x + i*sw - e, y + j*sh - e, sw + e*2, sh + e*2, preset)
      end
    end
  end
  -- 残留雾面：已刮掉的子格仍有 1 层银粉
  nvgBeginPath(vg); nvgRoundedRect(vg, x, y, cw, ch, 2)
  nvgFillColor(vg, nvgRGBA(200,205,212,50)); nvgFill(vg)
end
```

### 三种残留的模拟（这是"手刮"的灵魂）

| 残留 | 视觉 | 画法 |
|---|---|---|
| **银粉雾** | 刮过的地方纸色发灰 | 整格叠 `rgba(200,205,212,50)`，整格 `opened` 后降到 `20` 再淡出（200ms） |
| **刃痕** | 2–3 条浅色弧线 | 每格固定 2 条：`nvgBezierTo` 弧长 ≈ 格宽 ×0.8，线宽 **1.2dp**，`rgba(255,255,255,80)`；起点由 seed 决定 |
| **没刮到底的斑块** | 银层上若干"孤岛" | cover == 0 的子格若与已刮区不相邻，就自然成为孤岛——**这个效果是免费得到的**，不要额外画 |

**刮除粒子**：每 4 个子格被刮掉，喷 1 颗碎屑（直径 2–3dp，色取本格涂层中间色，寿命 0.5s，初速 60–140 dp/s 随机角，重力 400）。同屏 ≤ 64 颗。

## 13.5 页面高度核算（票面能塞进一屏吗）

这是 8 款皮肤 × 5 种布局组合时**唯一会崩的地方**：票面是纵向最长的组件，而 640dp 是死高度。所有组合必须过一遍这张表。

**固定开销（刮卡页）**

| 区块 | 高 |
|---|---|
| 状态栏安全区 | 44 |
| 顶栏 | 52 |
| 票面上间距 | 8 |
| 刻度进度条 | 30（含上下间距） |
| 刮刀工具条 | 52 + 10 |
| 按钮行 | 48 + 12 |
| 底部安全区 | 24 |
| **合计** | **280** |

→ 票面可用高度 = `640 − 280 = **360**`。**超过 360 的布局必须做减法。**

**票面自身高度公式**

```
TH = 12(上纸边) + 9(上纹带) + 32(票名区) + 26(玩法说明) + 54(对照号)
   + (格区高 + 9) + 34(票根) + 16(下纸边)
   = 192 + 格区高
```

| 布局 | 格区高 | 票面 TH | 页面总高 | 结论 |
|---|---|---|---|---|
| `L9` 3×3 | 295 | 487 | 767 | ❌ 超 127 → 压缩票名区/玩法说明/对照号（单号 44）后 `TH 424`，仍超 64 |
| **`L9` 最终** | 232（格高 72） | **388** | **668** | 仍差 28 → **允许票面滚动 28dp**（内容区 `overflow-y:auto`）。9 格版是唯一需要滚动的布局，因为 96dp 的大格不能压 |
| `L10` 2×5 | 314 | 506 | 786 | ❌ → 格高 58→44（格区 242）→ `TH 434` → 714 → 工具条折叠为 56×56 浮动按钮（−62）→ **652**，超出的 12 由 `flex` 吸收 ✔ |
| `L16` 4×4 | 186 | **378** | **658** | ⚠️ 差 18 → 玩法说明单行（−8）、票根 34→30（−4）、上纸边 12→10（−2）→ **644**，取 ±4 浮动 → **640 刚好** ✔ |
| `L20` 4×5 | 214 | 406 | 686 | ❌ 差 46 → 格高 38→34（格区 190）→ `TH 382` → 662；工具条收进底栏按钮行（−52）→ **610** ✔ |
| `L30` 6×5 | 190 | 382 | 662 | ❌ 差 22 → 同 L20（工具条进底栏）→ **610** ✔ |

**三条落地规则**（工程照此实现，不要临场改）

1. **`L16` 是唯一能「工具条常驻 + 全部内容一屏」的布局**，因此它是主推布局（§11.10 的默认值）。这也是选择 4×4 而不是 2×5 作为多格标准版的真正原因——不是美学，是尺寸约束。
2. `L10` / `L9` 走**紧凑档**（票名 24、玩法单行、格高 −8~−14），工具条折叠为右下角 `56×56` 浮动按钮。
3. `L20` / `L30` 的刮刀入口**常驻底栏按钮行**（48dp 行内左端 3 个小按钮），票面永远是全屏主体。

> 兜底顺序（所有「差 N dp」都按此消）：**先压上纸边与票根**（视觉损失最小）→ **再压格高**（影响刮感）→ **最后才允许滚动**。**绝不压号码字号**：号码可读性优先于版式完美。
