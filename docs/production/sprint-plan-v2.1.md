| **S2** | 多局 UI：多区、子块、逐格揭晓、性能 | 4 | 7 | 50 元 40 局三区票能在骁龙 600 系上 30fps 刮完 | G6 |

**为什么是这个顺序**：
1. **先地基后界面**。多局生成器不先跑通，界面做出来全是假的（金额、命中格、区合计都对不上）。
2. **S2 单独立批**。40 格三区是 v2.1 唯一的性能风险点（R15），必须有一整批专门打，不能挤在"界面重做"里。
3. **S3 才做决策**。三选一/预揭在 v2.0 文档里已定，但要用到多局票上，必须等多局 UI 完成（预揭要"露 2 局"而不是"露 2 格"）。
4. **S4 与 S3 可部分并行**。刮刀是独立模块（`bladeK()`/`consumeSharp()`/`sharpen()`），不依赖兑奖。
5. **S5 收口**。兑奖台是新增场所，放在最后一批，因为它要吃掉口、票奖级、广告 A7 三个接口。

| **「直接入账」可达** | 兑奖台首屏，与「全部兑奖」同尺寸；点了立即到账，金额不减 |
| **无任何付费/广告前置** | 走查：从 100% 涂层到看到合计，0 个广告、0 次扣费 |
| **兑奖动画可跳过且不减钱** | 点任意位置 → 立即到结果页；金额与不跳过时一致 |
| **A7 是 +50% 不是翻倍** | 1,000 的整叠，看广告变 1,500（+5% 叠加成后再 +50%） |
| **口袋永不过期** | 改系统时间 +30 天，票仍在 |
| **声明页不可跳过** | 返回键无效，只有「我已了解」 |
| **公示页 30 张表** | 与 CSV 字节级同源；改 CSV 不改页面则 CI 失败 |
| **撞名扫描通过** | `node tools/namecheck.mjs` 输出 0 命中；10 个票名 + 备选名全部通过 |
| **首日 60 秒** | 新号 10 次：≥2 次中奖 + ≥1 次跳变 + ≥1 次兑奖 + ≥1 次换刀；跳出率 <5% |
| **首日 15 分钟收支** | 余额落在 2.5 万-4 万（GDD 14.6 表），4 次升级可达 |

### 依赖

- **硬依赖 S1（奖级判定）+ S2（口袋入口）+ S4（广告位注册表）**。
- **需要主理人拍板（P0 阻塞）**：GDD L.1 的"信息免费"裁决是否确认。若主理人坚持"付费看结果"，本批需重做，且 PRD A13 与 G7 门禁作废——**这是本轮唯一一条需要升级决策的分歧**。
- **需要法务/审核口径确认**：票面可印「元」、奖金用「币」、公示"1 元 = 200 游戏币"，这套表述在 TapTap 审核口径下是否安全。若不安全，退到"票面只印档位数字，不印元"（成本 ≈ 0.5 天）。

### 风险与对策

| 风险 | 对策 |
|---|---|
| **兑奖台被做成收费站（R13）** | G7 门禁单独立项；评审时专门测"玩家能不能不做任何操作就说出金额" |
| 口袋满了挡住继续刮 | 口袋满时"选这张·刮"按钮变"先去兑奖"，但同时显示「直接入账」一键清空（无加成） |
| 公示 30 张表太长，玩家不看 | 按票种分页 + 首屏只显示玩家已解锁的票；未解锁的不展示（但可搜索） |
| 删除「一键揭晓」引发老玩家不适 | v0.8 从未上线，无人受影响；文档里明确写"这一条是用户明确要求" |
